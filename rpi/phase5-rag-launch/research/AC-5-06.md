# Research: AC-5-06 — System prompt Component 5 populated with retrieved chunks (not DB task fetch)

## Understanding

AC-5-06 is the **core RAG integration AC** for Phase 5. It replaces the Phase 4 placeholder
in `service.ts` Step 4 with a real `retrieveChunks()` call.

**Current state (Phase 4 placeholder):**
- Step 4 in `sendMessage()` fetches `TaskContentVariant` records from DB by `taskId`
- Only runs when `session.taskContext` is set (TASK_CARD / EMAIL_DEEPLINK entry points)
- Produces `kbChunks` with composite fake keys like `T08-constrained_couple`
- General chat (GENERAL entry point) gets `kbChunks = []` — no KB content at all

**Required state (Phase 5):**
- Step 4 calls `retrieveChunks()` for EVERY message — all entry points, all queries
- `retrieveChunks()` already exists and all 4 golden examples pass (AC-5-03/04)
- `kbChunks` populated from semantic search results, not task ID lookup
- `ChatMessage.retrievedChunks` stores real `KnowledgeBaseChunk.chunkKey` values
  (e.g. `["CHUNK_T08_constrained_couple", "CHUNK_T11_constrained_couple"]`)
  NOT Phase 4 format (`["T08-constrained_couple"]`)

**`taskName` + `consequenceLine` handling:**
These are NOT in `KnowledgeBaseChunk` — they come from `Task` + `TaskContentVariant` tables.
When `session.taskContext` exists, still fetch these from DB separately. This is correct
and does not violate any constraint — they serve Component 2 (task context), not Component 6 (KB).

**Verification:** Inspect `ChatMessage.retrievedChunks` in DB after sending a message.
Must contain `KnowledgeBaseChunk.chunkKey` values — not task IDs.

## Functions / Routes / Tests

**service.ts changes — Step 4:**

```typescript
import { retrieveChunks, type RetrievedChunk } from './rag/retrieval';

// In sendMessage(), replace the Phase 4 Step 4 block entirely:

// Step 4: RAG retrieval — replaces Phase 4 DB placeholder (C07, C13)
// Always run for every message — query drives retrieval, not taskContext.
let retrievedChunksResult: RetrievedChunk[] = [];
try {
  retrievedChunksResult = await retrieveChunks({
    query: content,
    personaKey: session.user.profile.personaKey,
    visaType: session.user.profile.visaType,
    city: session.user.profile.city,
    taskContext: session.taskContext,
  });
} catch (error) {
  // C13: embeddings.client.ts does NOT wrap OpenAI errors as AIFailureError.
  // Convert here so the outer catch emits SSE error event (not global handler).
  throw new AIFailureError(
    `RAG retrieval failed: ${error instanceof Error ? error.message : String(error)}`
  );
}

kbChunks = retrievedChunksResult.map(chunk => ({
  chunkKey: chunk.chunkKey,
  personaKey: session.user.profile!.personaKey,
  content: chunk.content,
  sourceName: chunk.sourceName,
  sourceUrl: chunk.sourceUrl,
}));

// Fetch taskName + consequenceLine separately (Component 2, not Component 6)
let taskName: string | null = null;
let consequenceLine: string | null = null;
if (session.taskContext) {
  const task = await db.task.findUnique({
    where: { id: session.taskContext },
    select: { name: true },
  });
  taskName = task?.name ?? null;

  const variant = await db.taskContentVariant.findFirst({
    where: {
      taskId: session.taskContext,
      personaKey: session.user.profile.personaKey,
    },
    select: { consequenceLine: true },
  });
  consequenceLine = variant?.consequenceLine ?? null;
}
```

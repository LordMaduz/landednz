# Research: AC-5-01 — generate-embeddings.ts runs on all KnowledgeBaseChunk records without error

## Understanding

Build a script at `apps/api/scripts/generate-embeddings.ts` that:
1. Reads all `KnowledgeBaseChunk` records where `embedding IS NULL`
2. Generates a 1536-dimension embedding for each chunk's `content` field
3. Updates the `embedding` column via raw SQL (`$queryRaw`)
4. Must NOT create the ivfflat index (that runs manually after, per C05)

Before the script can run, a Prisma migration must add the `embedding vector(1536)` column via raw SQL (C16 — cannot be expressed in Prisma schema syntax).

**Current state:**
- 42 `KnowledgeBaseChunk` records exist in the local DB (seeded from AC-2-15)
- The `embedding` column does NOT yet exist on the table
- No embedding-related migration has been created

**Verification:** After running the script, `SELECT count(*) FROM "KnowledgeBaseChunk" WHERE embedding IS NULL` returns 0.

## Ambiguities / Questions

### ~~Embedding provider~~ — FINALIZED

**DECISION: OpenAI text-embedding-3-small via `openai` npm package.**

The spec says "Anthropic text-embedding-3-small" but that's an OpenAI model (1536 dimensions). Anthropic has no embeddings API. Using OpenAI's text-embedding-3-small matches the spec's 1536 dimension requirement exactly.

**Implementation approach:**
- Add `openai` package to dependencies
- Create `shared/ai/embeddings.client.ts` (same isolation pattern as `claude.client.ts`)
- Add `OPENAI_API_KEY` to `config.ts` and `.env.example`
- C03 only restricts `@anthropic-ai/sdk`, so using `openai` package is architecturally sound

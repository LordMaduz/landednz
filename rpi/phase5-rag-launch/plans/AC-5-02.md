# Implementation Plan: AC-5-02

## Approach
Manual database operation only — no code or files to create. With AC-5-01 PASS (42/42 embeddings loaded), constitutional constraint C05 is now satisfied and the ivfflat index can be created. This is a one-time SQL command execution: `CREATE INDEX ON "KnowledgeBaseChunk" USING ivfflat (embedding vector_cosine_ops);` followed by verification via EXPLAIN query. The index must never appear in any migration file or script — it lives only in PostgreSQL. For verification on the 42-row dataset, `SET enable_seqscan = off` is used to force index usage since PostgreSQL's planner would correctly prefer a seq scan on such a small dataset.

None — this is a pure database operation that exists only in PostgreSQL. No code files, migration files, or scripts are created or modified.

## Implementation Order

5. Execute verification: `SET enable_seqscan = off; EXPLAIN SELECT id, "chunkKey", 1 - (embedding <=> $sample_vector::vector) AS similarity FROM "KnowledgeBaseChunk" ORDER BY embedding <=> $sample_vector::vector LIMIT 5;`
6. Confirm EXPLAIN output shows "Index Scan" (not "Seq Scan")

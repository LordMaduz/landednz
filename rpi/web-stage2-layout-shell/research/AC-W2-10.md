responds correctly at all 5 required breakpoints using the dev server.

| Width | Sidebar | Nav labels | Mobile hamburger |
|-------|---------|-----------|-----------------|

## Ambiguities / Questions

**One consideration surfaced:** The auth middleware now redirects `/roadmap`, `/chat`,
`/settings` to `/auth/signin`. For responsive verification of the sidebar, we should use
`/auth/signin` page which still renders through the `(marketing)` layout (no sidebar) —
or we need to disable middleware temporarily.

**Resolution**: The `/auth/signin` page is in the `(marketing)` route group and has NO
sidebar — it's the wrong page to verify sidebar responsive behavior. We have two options:
1. Use the existing dev server with a browser that has no session cookie → navigate to
   `/roadmap` → will redirect, but BEFORE redirect, the sidebar components are compiled
   correctly. The redirect itself can be verified by looking at the compiled HTML.
2. Temporarily check the layout via the page source/HTML structure at `/auth/signin?redirect=/roadmap`.

Actually, the simplest verification: since this is a visual check, the user would navigate
to `/roadmap` in the browser, get redirected to `/auth/signin`, but the sidebar LAYOUT
SHELL can still be verified by temporarily adding a Playwright bypass or by checking the HTML
source of the rendered page.

Wait — actually this is simpler. The auth middleware redirects happen server-side BEFORE
rendering. The responsive CSS behavior exists in the compiled assets regardless. We can:
1. Navigate to `/auth/signin` which uses the marketing layout (no sidebar to test)
2. Navigate to a protected route with a cookie temporarily set

**Resolution chosen**: Use fake cookie bypass (Option B). Open browser devtools, set cookie `sb-dev=1` on `localhost:3000`, navigate to `/roadmap` — middleware detects `sb-` prefix and allows through. No code changes needed. Delete cookie after verification.

This bypasses the middleware `sb-` prefix check without modifying code.

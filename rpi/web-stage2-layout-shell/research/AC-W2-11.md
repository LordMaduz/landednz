# Research: AC-W2-11 — Playwright E2E: all routes, correct layout at 1280 + 768

## Understanding

AC-W2-11 is the final AC for Web Stage 2. Build a Playwright E2E test suite that
programmatically verifies:

1. **All 6 routes** respond at the correct HTTP status (navigable)
2. **Correct layout at 1280px** — app routes show sidebar, marketing routes don't
3. **Correct layout at 768px** — app routes show collapsed sidebar (still visible), mobile hamburger absent at this exact threshold

**Auth middleware context**: Protected routes (/roadmap, /chat, /settings) redirect to
/auth/signin without a session. Tests must inject the `sb-dev=1` cookie (same approach as
AC-W2-10 visual check) via `page.context().addCookies()` to bypass the middleware and reach
the sidebar layout.

**What "correct layout" means:**
- 1280px: `<aside>` element is visible, sidebar has `xl:w-sidebar` class (256px), text labels visible
- 768px: `<aside>` element is visible, sidebar uses `w-sidebar-collapsed` classes (64px)
- Marketing routes: no `<aside>` element

## Files Involved

**Install:**
- `@playwright/test` as devDependency in apps/web
- Run `npx playwright install chromium` for browser binary

**Create:**
- `apps/web/playwright.config.ts` — config with 2 viewport projects (1280px + 768px)
- `apps/web/e2e/layout.spec.ts` — E2E tests for all 6 routes at both breakpoints

**Modify:**
- `apps/web/package.json` — add `"test:e2e": "playwright test"` script

## Functions / Routes / Tests

**playwright.config.ts:**
```typescript
import { defineConfig, devices } from '@playwright/test'

export default defineConfig({
  testDir: './e2e',
  webServer: {
    command: 'npm run dev',
    url: 'http://localhost:3000',
    reuseExistingServer: true,
  },
  use: { baseURL: 'http://localhost:3000' },
  projects: [
    { name: 'desktop', use: { ...devices['Desktop Chrome'], viewport: { width: 1280, height: 800 } } },
    { name: 'tablet', use: { ...devices['Desktop Chrome'], viewport: { width: 768, height: 1024 } } },
  ],
})
```

**e2e/layout.spec.ts — test cases:**

1. At 1280px — app routes (with sb-dev=1 cookie):
   - `/roadmap` → `<aside>` visible, sidebar has full width class
   - `/chat` → `<aside>` visible
   - `/settings` → `<aside>` visible

2. At 1280px — marketing routes (no cookie needed):
   - `/` → no `<aside>` element
   - `/onboarding` → no `<aside>` element
   - `/auth/signin` → no `<aside>` element

3. At 768px — app routes (with sb-dev=1 cookie):
   - `/roadmap` → `<aside>` visible (collapsed sidebar still rendered)

4. Auth redirect verification (no cookie):
   - `/roadmap` → redirects to `/auth/signin?redirect=%2Froadmap`

## Constraints That Apply

- No constitutional violations — tests are devDependency only, no app code changes
- `reuseExistingServer: true` — avoids starting duplicate dev server if one is already running

# Research: AC-W2-02 — Marketing layout at `/`: full-width, no sidebar

## Understanding

Create the Next.js App Router `(marketing)` route group containing the landing page at `/`.
The marketing layout wraps only the landing page — full-width, no sidebar. The background
and fonts are already applied by the root layout (AC-W2-01).

**Canonical structure from 15-web-build-specification.md:**
```
app/
├── (marketing)/
│   ├── layout.tsx     ← marketing layout (full-width, no sidebar)
│   └── page.tsx       ← landing page placeholder at /
├── (app)/             ← built in later ACs (AC-W2-03+)
├── onboarding/        ← outside groups, no shared layout
├── auth/signin/       ← outside groups, no shared layout
├── layout.tsx         ← root layout (AC-W2-01, already done)
└── globals.css
```

**Important:** `/onboarding` and `/auth/signin` are NOT in the `(marketing)` group — they
live outside route groups with no shared layout (per the spec). Only `/` goes in `(marketing)`.

The current `apps/web/src/app/page.tsx` (Stage 1 design-token test) conflicts with
`(marketing)/page.tsx` — both claim `/`. The root-level `page.tsx` must be deleted and
replaced by `(marketing)/page.tsx` as a Stage 2 placeholder.

**Marketing layout:** Minimal wrapper — `min-h-screen` and nothing else. No sidebar,
no nav (that's Stage 3 content). Background (`bg-bg`) is already inherited from root `<body>`.

**Placeholder page:** The spec says "placeholder text visible" — a minimal RSC with a
heading like "Landing Page — coming in Stage 3" is sufficient for this AC.

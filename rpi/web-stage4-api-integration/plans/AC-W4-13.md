# Implementation Plan: AC-W4-13 — Loading states use skeleton components

## Approach

Add skeleton loading states to 3 locations using the existing Stage 1 `Skeleton` component. It is already CW03-compliant — `skeleton-pulse` animation lives inside `@media (prefers-reduced-motion: no-preference)` in globals.css. (1) Create `loading.tsx` — the Next.js App Router convention that auto-shows while the RSC fetches `GET /roadmap`. (2) Modify `TaskDetail.tsx` — `detail === undefined` means "still fetching", show skeleton blocks instead of "coming soon" text. (3) Modify `ChatPanel.tsx` — `sessionId === null && !sessionError` is the session init window, show skeleton message bubbles.

## Implementation Order

1. **Create `loading.tsx`** — roadmap page skeleton: `Skeleton variant="card"` for hero, local `TaskRowSkeleton` helper (circle + 2 text lines + width block) repeated 3×, filter tab skeleton, phase header + 2 more rows.

2. **Modify `TaskDetail.tsx`** — add local `TaskDetailLoadingSkeleton` function (4 skeleton blocks: section label + 3 text lines, repeated for steps/documents/source). Change the existing `{detail ? ... : 'coming soon'}` to a 3-way conditional:
   - `detail === undefined` → `<TaskDetailLoadingSkeleton />`
   - `detail` (object) → existing rich content
   - fallthrough → "coming soon" text (unreachable in practice but kept for type safety)

3. **Modify `ChatPanel.tsx`** — import `Skeleton`. In the messages area conditional, add first branch: `sessionId === null && !sessionError` → 2 skeleton message bubbles (wide + narrow, different alignments).

4. **TypeScript check** — `npx tsc --noEmit` from `apps/web` → 0 errors.

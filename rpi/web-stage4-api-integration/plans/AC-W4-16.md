# Implementation Plan: AC-W4-16 — Playwright E2E: full user journey

## Approach

Write a Playwright E2E test that exercises the full journey: sign in → onboard → roadmap → open task → mark complete → verify update. Auth is handled via a `global-setup.ts` that uses the Supabase admin API to generate a magic link (no UI interaction, no email), navigates the Playwright browser to the generated link, lets the existing `/auth/callback` route exchange the code for a real session, then saves auth cookies to `playwright-auth.json`. The journey spec loads this saved state. After each run, `global-teardown.ts` deletes the test user so the test is re-runnable from a clean state. No app-side test routes are added. No auth is mocked. The journey test runs only at desktop-1280 via a dedicated `e2e-journey` Playwright project. Existing 5-viewport projects are scoped via `testMatch` to exclude `journey.spec.ts`.

## Implementation Order

1. **Create `e2e/global-setup.ts`** — Uses `@supabase/supabase-js` with service role key. Creates test user (`e2e-test@landednz.dev`) via `supabase.auth.admin.createUser({ email, email_confirm: true })`. Generates magic link via `supabase.auth.admin.generateLink({ type: 'magiclink', email })`. Launches a Playwright browser, navigates to the `properties.action_link` URL (Supabase verifies token → redirects to `/auth/callback?code=...` → existing callback route exchanges code → sets session cookies). Waits for URL to be `/roadmap` or `/onboarding`. Saves context state to `e2e/playwright-auth.json`. Saves test user ID to `e2e/.e2e-user-id` for teardown. Credentials via env vars.

2. **Create `e2e/global-teardown.ts`** — Reads user ID from `e2e/.e2e-user-id`, calls `supabase.auth.admin.deleteUser(userId)` to delete test user + cascade-delete Prisma profile. Removes `e2e/.e2e-user-id` and `e2e/playwright-auth.json`.

3. **Create `e2e/journey.spec.ts`** — Single test. Steps:
   - `page.goto('/roadmap')` → expect redirect to `/onboarding`
   - Q1: click `getByText('Accredited Employer Work Visa')`
   - Q2: click `getByText('Auckland')`
   - Q3: click `getByText('Arriving alone')`
   - Q4: click `getByText('Technology / Engineering')`
   - Q5: click `getByText('More than 2 months ago')`
   - Wait for "See my roadmap →" button, click it
   - Wait for URL `/roadmap`, wait for task rows to appear
   - Click first `[data-testid="task-row"]` or fallback to first priority task visible text
   - Wait for task detail heading visible
   - Click `getByRole('button', { name: 'Mark as done' })`
   - Expect `getByText('Saving…')` to appear then disappear
   - Expect URL still `/roadmap` (panel closed, back to list)

4. **Modify `playwright.config.ts`** — Add `globalSetup: './e2e/global-setup.ts'` and `globalTeardown: './e2e/global-teardown.ts'`. Add `testMatch: /layout\.spec\.ts|visual\.spec\.ts/` to each of the 5 existing viewport projects. Add new `e2e-journey` project: desktop-1280 viewport, `use: { storageState: './e2e/playwright-auth.json' }`, `testMatch: /journey\.spec\.ts/`.

5. **Run test** — `cd apps/web && npx playwright test --project=e2e-journey` → 1 test green.

# Implementation Plan: AC-W4-03 — Sign out: clears session, redirects to `/`, subsequent `/roadmap` → redirect to sign in

## Approach

Wire the existing no-op "Sign out" button in `SettingsView.tsx` to real Supabase sign-out logic.
Add `handleSignOut` which calls `supabase.auth.signOut()` (browser client) then `router.push('/')`.
The middleware upgraded in AC-W4-02 already handles subsequent protected-route access correctly —
no middleware changes needed.

## File Changes

- **Modify** `apps/web/src/components/settings/SettingsView.tsx` — import `createClient` from
  `@/lib/supabase/client`, import `useRouter` from `next/navigation`, add `handleSignOut` async
  function, replace `onClick={() => {}}` on Sign out button with `onClick={handleSignOut}`

No new files. No Storybook story changes (behaviour only, no visual change).

## Implementation Order

1. Add `useRouter` import from `next/navigation`
2. Add `createClient` import from `@/lib/supabase/client`
3. Add `const router = useRouter()` inside the component
4. Add `handleSignOut` async function:
   ```typescript
   const handleSignOut = async () => {
     const supabase = createClient()
     await supabase.auth.signOut()
     router.push('/')
   }
   ```
5. Replace `onClick={() => {}}` on Sign out Button with `onClick={handleSignOut}`
6. Run `npx tsc --noEmit` in `apps/web`

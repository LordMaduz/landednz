# Implementation Plan: AC-W4-06

## Approach

Fix the priority order bug in the existing `deriveCardState()` function in `roadmap-mapper.ts`,
then write Vitest unit tests covering all derivation paths. The function was created during
AC-W4-05 but has the wrong priority order: current code checks `isBlocked` before `IN_PROGRESS`
and `taskType === 'PREMIUM'` before `IN_PROGRESS`. The `web-component-patterns` skill specifies
the correct order: COMPLETE → IN_PROGRESS → premium_locked → blocked → not_started. The fix is
4 lines. No new files beyond the test file.

## Implementation Order

1. Fix `deriveCardState` priority order in `roadmap-mapper.ts`:
   ```typescript
   export function deriveCardState(task: RoadmapApiTask): TaskCardState {
     if (task.status === 'COMPLETE') return 'complete'
     if (task.status === 'IN_PROGRESS') return 'in_progress'
     if (task.taskType === 'PREMIUM') return 'premium_locked'
     if (task.isBlocked) return 'blocked'
     return 'not_started'
   }
   ```
2. Create `apps/web/src/lib/roadmap-mapper.test.ts` with all 8 test cases (see Test Strategy)
3. Run `npm run test` from `apps/web/` — all tests must pass (including existing cn.test.ts)
4. Run `npx tsc --noEmit` from `apps/web/` — zero errors

# Implementation Plan: AC-W4-01 — Google OAuth end-to-end on web, session persists on refresh

## Approach
Install `@supabase/supabase-js` and `@supabase/ssr`, create Supabase browser + server client helpers,
wire the existing `AuthCard` Google button to `supabase.auth.signInWithOAuth()`, and create a Next.js
Route Handler at `/auth/callback` that exchanges the OAuth code for a session (setting HTTP-only
cookies via `@supabase/ssr`) and then calls `POST /auth/verify` on the Fastify API to upsert the
user into the Prisma DB before redirecting to `/roadmap`. No session data, tokens, or auth state
stored in localStorage or Zustand — auth state lives entirely in Supabase SSR cookies.

## File Changes

**New files:**
1. `apps/web/src/lib/supabase/client.ts` — browser client (`createBrowserClient()` from `@supabase/ssr`)
2. `apps/web/src/lib/supabase/server.ts` — server client (`createServerClient()` with `getAll`/`setAll` cookie pattern for Route Handlers)
3. `apps/web/src/app/(marketing)/auth/callback/route.ts` — GET handler: reads `code` + `redirect` query params, calls `supabase.auth.exchangeCodeForSession(code)`, calls `POST /auth/verify`, redirects to `/roadmap`
4. `apps/web/.env.local` — `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `NEXT_PUBLIC_API_URL`

**Modified files:**
5. `apps/web/src/components/auth/AuthCard.tsx` — replace `handleGoogleClick` setTimeout stub with real `signInWithOAuth({ provider: 'google', options: { redirectTo: window.location.origin + '/auth/callback' } })`; keep `google_loading` state until redirect
6. `apps/web/package.json` — add `@supabase/supabase-js` and `@supabase/ssr` as dependencies

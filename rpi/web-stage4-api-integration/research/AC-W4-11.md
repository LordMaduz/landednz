# Research: AC-W4-11 — Premium gate upgrade → Stripe Checkout → return with ?upgrade=success → Phase 3 unlocked

## Understanding

The "Upgrade" button on `PremiumGateCard` currently calls an empty `onUpgrade` callback (`() => {}`). This AC wires it to redirect the user to Stripe's hosted Checkout page (redirect mode — no embedded payment form). After payment, Stripe redirects back to `/roadmap?upgrade=success`, and the UI shows a success state ("Phase 3 unlocked").

**Intended flow:**
1. User clicks "Continue with Premium — $49 for 6 months"
2. Web app calls a Route Handler (`/api/checkout`) → creates a Stripe Checkout session → returns `{ url }` 
3. Browser redirects to `stripe.com/checkout/...`
4. User pays with test card
5. Stripe redirects back to `/roadmap?upgrade=success`
6. Roadmap page detects `?upgrade=success` query param → shows success toast/banner + re-fetches roadmap

## Ambiguities / Questions

**This AC has 3 blocking issues that must be resolved before planning:**

---

**Issue 1 — No Stripe keys configured anywhere.**

Neither the root `.env.local`, `apps/web/.env.local`, nor `.env.example` contains any Stripe keys. The required keys per spec are:
- `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY`
- `STRIPE_SECRET_KEY`
- `STRIPE_PRICE_ID_BIANNUAL` (the $49 / 6-month price)
- `STRIPE_WEBHOOK_SECRET`

The `stripe` npm package is also not installed in the web app. **Without a configured Stripe account and price IDs, this AC cannot be implemented or verified.**

**Question 1:** Do you have a Stripe test account with a product and price set up? If so, provide the keys and price ID. If not, should this AC be deferred?

---

**Issue 2 — No Stripe webhook backend to activate the subscription.**

The verification requirement is "Phase 3 unlocked". For premium tasks to actually unlock, the backend needs `Subscription.isActive = true` for the user. This requires:
- A Stripe webhook receiver that catches `checkout.session.completed`
- Creates/updates the `Subscription` record in the DB

The backend Phase 3 is **DEFERRED** — no `/subscription/webhook` endpoint exists in Fastify. Even if Stripe checkout completes successfully, the user's subscription won't be activated in the DB and Phase 3 tasks will still return 403.

**Question 2:** Should "Phase 3 unlocked" be implemented as visual-only (detect `?upgrade=success`, dismiss the premium gate card UI), understanding that Phase 3 tasks will still be API-locked until Phase 3 backend is built?

---

**Issue 3 — `stripe` package not installed in the web app.**

Stripe SDK (`stripe` npm package for the server-side Route Handler) is not installed. This needs to be added.

# Research: AC-W4-09 — Chat SSE streaming: tokens progressive, citations render, source footer

## Understanding

Replace the Stage 3 mock chat simulation in `ChatPanel.tsx` with real API-backed SSE streaming.

Two API calls are involved:
1. **Session creation** — `POST /chat/sessions` with `{ entryPoint, taskContext? }` → returns `{ sessionId, openingMessage }`. The opening message is a personalised plain string (not structured ChatResponse). This call requires an active subscription (403 if not).
2. **Message streaming** — `POST /chat/sessions/:sessionId/messages` with `{ content }` → SSE stream of `{ type: 'chunk', text }` events, terminated by `{ type: 'done' }` or `{ type: 'error', message }`.

Current `ChatPanel.tsx` has a step-based state machine (step 0→1→2→3) driving simulated thinking delays and `getMockResponse()` returning rich `ChatResponse` objects. All of that gets replaced with real fetch calls and ReadableStream SSE consumption.

**Token access problem:** `ChatWidget` is currently rendered in the layout with no token. The layout is already a server component — it can call `createClient()` + `getSession()` and pass the token as a prop to `ChatWidget`, then to `ChatPanel`. This follows the established pattern from the roadmap page.

**Citation/source extraction:** The backend SSE stream only emits `{ type: 'chunk', text }` and `{ type: 'done' }` — no structured source metadata. Sources are embedded in the KB chunks fed to the LLM system prompt, so the LLM may mention domain names inline. After the stream completes, extract NZ government/official domain patterns from the full response text via regex (e.g., `ird.govt.nz`, `immigration.govt.nz`, `acc.co.nz`) and display them in the existing `SourcePill` footer.

**`api.ts` additions:**
```typescript
export interface CreateSessionResponse {
  sessionId: string
  openingMessage: string
}

export async function createChatSession(
  entryPoint: ChatEntryPoint,
  token: string,
  taskContext?: string,
): Promise<CreateSessionResponse>

export async function streamChat(
  sessionId: string,
  content: string,
  token: string,
  onChunk: (text: string) => void,
  onDone: () => void,
  onError: (message: string) => void,
): Promise<void>
```

**Session init on mount:**
- Call `createChatSession(entryContext, token)` → set `sessionId`
- Add opening message as first AI bubble: `{ type: 'plain', text: openingMessage }`
- On 403: set `sessionError` → show inline error in panel ("Chat is available on premium plans")

**`handleSend`:**
1. Add user message to list
2. `setIsStreaming(true)`, `setStreamingText('')`
3. Call `streamChat(...)`:
   - `onChunk`: append to `streamingText`
   - `onDone`: convert `streamingText` to completed AI message (extract sources from text, add to message), `setIsStreaming(false)`, `setStreamingText('')`
   - `onError`: add error AI message, `setIsStreaming(false)`

**Source extraction helper:**
```typescript
function extractSources(text: string): string[] {
  const nzDomainRegex = /\b([a-zA-Z0-9-]+\.(?:govt\.nz|co\.nz|org\.nz|ac\.nz))\b/g
  const matches = [...new Set(text.match(nzDomainRegex) ?? [])]
  return matches
}
```

## Ambiguities / Questions

**Ambiguity 1 — Subscription gate handling:**
`POST /chat/sessions` returns 403 if the user has no active subscription. Most dev users won't have `Subscription.isActive = true`. Options:
- **A**: Show an inline error in the chat panel: "Chat requires a premium subscription. Upgrade to access the AI advisor." (with a link to `/roadmap` for the upgrade flow — AC-W4-11 handles Stripe)
- **B**: Seed the dev DB with a subscription row for the test user so chat works in local dev

Option A is safer (no DB seed dependency). But it means AC-W4-09 can't be fully verified locally unless the dev DB has a subscription row.

**→ Recommend Option A (inline error) + confirm that for verification purposes you'll manually insert a subscription row in the dev DB.**

**Ambiguity 2 — Source/citation extraction:**
The backend SSE stream has no structured source metadata. The `done` event is just `{"type":"done"}`. Sources only exist in the LLM's natural language output. Options:
- **A**: Regex-extract NZ gov domains from response text, show in `SourcePill` footer
- **B**: Show no source footer for streaming messages (citations are a Stage 5 concern)
- **C**: Add a `sources` event to the backend SSE stream (requires backend change — out of scope)

Option A is achievable without backend changes and satisfies "citations render, source footer" in the AC. Option B is simpler but doesn't meet the AC. Option C is out of scope.

**→ Recommend Option A (regex extraction). Confirm?**

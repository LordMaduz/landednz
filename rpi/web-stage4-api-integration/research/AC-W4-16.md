# Research: AC-W4-16 — Playwright E2E: sign in → onboard → roadmap → open task → mark complete → verify update

## Understanding

A full Playwright E2E journey test that runs against the local API. The journey covers:
sign in → onboard → roadmap (loads real tasks) → click task (fetches detail) → mark complete → verify task status updates.

**Auth strategy**: Google OAuth cannot be automated in Playwright (requires real browser-Google interaction). The correct approach is `global-setup.ts` that signs in programmatically using Supabase `signInWithPassword()` with a dedicated e2e test user (email + password), extracts the session, injects it as browser cookies, and saves to `playwright-auth.json`. The journey test then starts already authenticated — no sign-in UI interaction needed.

**Onboarding form**: After auth injection, navigating to `/roadmap` redirects to `/onboarding` if no profile exists. The test fills the onboarding form (visa type, arrival date, skill area), submits, and verifies the redirect to `/roadmap`.

**Teardown**: `global-teardown.ts` deletes the test user via Supabase admin API so the test can be re-run from a clean state.

**Single project**: Journey test runs at `desktop-1280` only (not all 5 viewports — this is a functional E2E, not a responsive test).

# Research: AC-W4-10 — Chat entry-point-aware: TASK_CARD sends taskId, ROADMAP sends context

## Understanding

The chat panel currently always creates sessions with `entryPoint: 'ROADMAP'` (hardcoded in `ChatWidget.tsx` line 26). This AC wires up two distinct entry points:

1. **TASK_CARD** — when user opens chat via "Ask a question" in `TaskDetail`. Must send `taskContext: task.taskId` (the task ID string, e.g. `T08`). The backend looks up the task name from DB and uses it in the opening message: *"You're looking at the IRD Number task. I know…"*

2. **ROADMAP** — when user opens chat via the floating FAB button (current default). Sends no taskContext. Opening message references tasks completed: *"Hi Ruchira — you've completed 3 tasks so far. What would you like to know about settling in Auckland?"*

**The problem:** `ChatWidget` lives in the layout (rendered globally). `TaskDetail` is inside the roadmap page. There's no direct prop path between them since the layout is a server component. The solution is a minimal Zustand `chatStore` to carry the entry point + optional taskId, which both components can read/write.

**Backend validation note:** `POST /chat/sessions` returns 400 if `entryPoint: 'TASK_CARD'` is sent without `taskContext`. The web client must always pass `taskId` when using `TASK_CARD`. The backend expects `taskContext` as the task ID string (not the name) — it fetches the name itself.

## Functions / Routes / Tests

**`chatStore.ts`:**
```typescript
interface ChatStore {
  isOpen: boolean
  entryPoint: ChatEntryPoint
  taskId: string | null
  open: (entryPoint: ChatEntryPoint, taskId?: string) => void
  close: () => void
}
```

**`ChatWidget.tsx` changes:**
- Remove `const [chatOpen, setChatOpen] = useState(false)`
- Subscribe to `useChatStore` for `isOpen`, `open`, `close`
- FAB `onClick` calls `open('ROADMAP')` (no taskId)

**`ChatPanel.tsx` changes:**
- Accept `taskId?: string` prop (forwarded from ChatWidget via store)
- In `initSession()`: call `createChatSession(entryContext ?? 'ROADMAP', token, taskId ?? undefined)`
- No other changes needed — `api.ts` already accepts `taskContext?: string`

**`TaskDetail.tsx` changes:**
- Add `onOpenChat?: () => void` to `TaskDetailProps`
- Wire "Ask a question" button: `onClick={onOpenChat}`

**`RoadmapView.tsx` changes:**
- Import `useChatStore`
- Pass `onOpenChat={() => { useChatStore.getState().open('TASK_CARD', selectedTask.taskId) }}` to `TaskDetail`

2. Click task → "Ask a question" → same endpoint with `{"entryPoint":"TASK_CARD","taskContext":"T08"}` → opening message names the task

## Constraints That Apply

- **CW01**: No Tailwind arbitrary values — no CSS changes in this AC
- **CW04**: `ChatEntryPoint` already in `@landednz/types`, import from there
- **CW06**: Zustand is memory-only (session state) — does not use localStorage. Auth still via Supabase SSR cookies.
- **Backend constraint**: `TASK_CARD` requires `taskContext` — always pass `taskId` when entry point is `TASK_CARD`
- **AC-W4-15 relationship**: AC-W4-15 builds the full `chatStore` with messages + streaming state. This AC creates a minimal version (`isOpen + entryPoint + taskId` only). AC-W4-15 will expand it — design the store interface so AC-W4-15 can extend it.

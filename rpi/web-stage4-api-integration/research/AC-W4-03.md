# Research: AC-W4-03 — Sign out: clears session, redirects to `/`, subsequent `/roadmap` → redirect to sign in

## Understanding

The "Sign out" button in `SettingsView.tsx` is currently a no-op stub (`onClick={() => {}}`).
This AC wires it to real Supabase sign-out logic.

Flow:
1. User clicks "Sign out" in Settings
2. `supabase.auth.signOut()` is called — Supabase SSR clears the session cookies
3. `router.push('/')` redirects user to the landing page
4. Subsequent `/roadmap` access → middleware (now real from AC-W4-02) detects no session → redirects to `/auth/signin?redirect=/roadmap`

Nothing about this AC requires new files or new UI. It's purely behaviour wiring.

AC-W4-15 ("Reset on sign out" for Zustand stores) is a separate concern — not in scope here.

## Files Involved

**Modified only — no new files:**
- `apps/web/src/components/settings/SettingsView.tsx` — import `createClient` (browser), import `useRouter`, implement `handleSignOut` async function, wire to Sign out button

## Functions / Routes / Tests

**`handleSignOut` in `SettingsView.tsx`:**
```typescript
const router = useRouter()

const handleSignOut = async () => {
  const supabase = createClient()
  await supabase.auth.signOut()
  router.push('/')
}
```

Wire to the Sign out button: `onClick={handleSignOut}`

**No tests** — verification is manual (click sign out, confirm redirect to `/`, then confirm `/roadmap` redirects to signin).

## Constraints That Apply

- **CW06**: Auth via Supabase SSR cookies only. `signOut()` clears cookies — no manual localStorage cleanup needed.
- `SettingsView` is already `'use client'` — browser Supabase client and `useRouter` are safe to use here.
- No Storybook story changes needed — no visual change, only behaviour.

**Current (wrong) order:** COMPLETE → blocked → premium_locked → IN_PROGRESS → not_started

**Correct order per `web-component-patterns` skill:**
```
COMPLETE → IN_PROGRESS → premium_locked → blocked → not_started
```

Why the order matters:
- `in_progress` before `premium_locked` — a user who has started a task should see in_progress,
  not the premium lock (they must have had a subscription to start it)
- `premium_locked` before `blocked` — a free-tier user should see the premium lock, not a
  dependency lock (the skill comment: "free-tier user sees the premium lock, not a dependency lock")

## Functions / Routes / Tests

### `deriveCardState(task: RoadmapApiTask): TaskCardState` — fix priority order

Corrected implementation:
```typescript
export function deriveCardState(task: RoadmapApiTask): TaskCardState {
  if (task.status === 'COMPLETE') return 'complete'
  if (task.status === 'IN_PROGRESS') return 'in_progress'
  if (task.taskType === 'PREMIUM') return 'premium_locked'
  if (task.isBlocked) return 'blocked'
  return 'not_started'
}
```

Note: No `userTier` parameter needed. Phase 3 (monetisation) is deferred — all users are
currently FREE. `task.taskType === 'PREMIUM'` is the correct proxy for now. `userTier` will
be added when Phase 3 / AC-W4-11 is implemented.

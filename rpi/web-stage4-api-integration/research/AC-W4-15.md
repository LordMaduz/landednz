# Research: AC-W4-15 — Zustand stores: roadmapStore + chatStore, persist across nav, reset on sign out

## Understanding

The spec requires two Zustand stores to hold cross-navigation state so that navigating away from /roadmap and returning doesn't lose the user's context:

- **roadmapStore**: holds `roadmapData` (API response), `filter`, `selectedTask`, and supports optimistic updates. Currently all live in `RoadmapView.tsx` as `useState`.
- **chatStore**: already has `isOpen`, `entryPoint`, `taskId`. Needs extending with `messages` and `streaming` state (currently in `ChatPanel.tsx` as `useState`).
- **Persist across nav**: Next.js App Router re-mounts page components on route change. Zustand is module-level singleton — state survives route changes. Moving roadmap state to the store means the user's selected task and filter survive a /settings round-trip.
- **Reset on sign out**: SettingsView currently calls `supabase.auth.signOut()` + `router.push('/')`. Both stores need a `reset()` action called here — without it, the next user's session on the same browser would see stale data.

**RSC hydration pattern**: `page.tsx` fetches `initialData` server-side and passes it as a prop. On `RoadmapView` mount, if the store is empty (null), hydrate it from `initialData`. Subsequent mounts (navigate back) skip hydration since store already has data.

**Chat messages + sessions**: `sessionId` stays as component-local state (it belongs to the current session connection). Messages go in the store, but `chatStore.close()` also clears messages so each open starts fresh with the opening message. This avoids showing old messages with a new sessionId (confusing context mismatch). "Persist across nav" for chat means: navigate while chat is open — the layout keeps ChatWidget + ChatPanel mounted, so messages naturally persist without Zustand changes. The store just ensures streaming state is accessible globally.

## Ambiguities / Questions

**One ambiguity resolved:**
- `gateState` (PremiumGateState) is currently in RoadmapView but not mentioned in the spec. Including it in roadmapStore makes sense since it's UI state that should persist across nav (dismissed premium gate shouldn't re-appear). This is a pragmatic extension.

**Decision on chat messages:**
- Messages go in chatStore, but chatStore.close() clears them (not just `isOpen=false`). This prevents stale message context after re-open with a new session. This departs slightly from spec's "persist" language but avoids a confusing UX bug.

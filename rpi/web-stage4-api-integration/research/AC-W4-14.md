# Research: AC-W4-14 — Error handling (retry card, 401 redirect, inline errors, chat system message)

## Understanding

Four distinct error scenarios need proper UI treatment:

1. **Network error (roadmap page load)** → a "retry card" — a recoverable UI with a "Try again" button. Currently `page.tsx` catches all non-404 errors and passes `null` as `initialData`, rendering an empty roadmap with no feedback.

2. **401 Unauthorized** → redirect to `/auth/signin`. Applies to both the roadmap (page load + task complete + task detail) and the chat session init. Currently: roadmap page treats 401 as a generic error; ChatPanel shows a generic error string.

3. **500 / other server error** → inline error message within the page content. Currently shows an empty roadmap (null initialData with no error UI).

4. **Chat failure** → system message in the chat thread. `onError` in ChatPanel already renders a plain AI message — but 401 chat errors should redirect rather than show the message.

## Files Involved

**Create:**
- `apps/web/src/app/(app)/roadmap/error.tsx` — Next.js App Router error boundary for the route. Catches unhandled server errors (network errors from page.tsx if re-thrown). Shows retry card with "Try again" button that calls `reset()`.

**Modify:**
- `apps/web/src/app/(app)/roadmap/page.tsx` — Add 401 handling (redirect to sign-in). Re-throw network-level errors so error.tsx catches them; keep null-passthrough for 500 server errors.
- `apps/web/src/components/roadmap/RoadmapView.tsx` — When `initialData === null`, render inline error card instead of empty roadmap. In `handleTaskClick` catch: if 401, redirect; otherwise set a `taskDetailError` flag on the selected task (or use a local error state).
- `apps/web/src/components/roadmap/TaskDetail.tsx` — Accept `detailLoadError?: boolean` prop; show inline error message in the detail area when true.
- `apps/web/src/components/chat/ChatPanel.tsx` — In session init catch: if status 401, call `router.push('/auth/signin?redirect=/roadmap')` instead of setting `sessionError`. In `onError` callback: if error message contains "401" or "Unauthorized", redirect instead of showing system message.

- `'use client'` directive required for Next.js error boundary
- Props: `{ error: Error, reset: () => void }`

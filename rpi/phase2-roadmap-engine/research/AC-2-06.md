# Research: AC-2-06 — GET /roadmap correct topThree for golden1 scenario

## Understanding

AC-2-06 builds the `GET /roadmap` route — the core read path of the roadmap engine. It reads the user's stored `UserRoadmapEntry` records (priorityScore + isBlocked already computed at onboarding), joins Task and TaskContentVariant data, and returns:
- `topThree`: top 3 non-complete, non-blocked tasks sorted by priorityScore DESC
- `phases`: all tasks grouped by phase (1, 2, 3)
- `lastComputedAt`: timestamp of last roadmap computation

The route does NOT recalculate scores — it reads stored `priorityScore` from `UserRoadmapEntry`. Scores are recomputed separately (AC-2-11: daily job).

**AC-2-06 verification:** Golden1 scenario (constrained_couple, Day 2, no completions) must return correct topThree task IDs.

## Functions / Routes / Tests

### Route contract (from spec §4.3.2)

```typescript
GET /roadmap
Authorization: Bearer <jwt>

// Response 200:
interface RoadmapResponse {
  topThree: RoadmapTask[];       // top 3 non-complete, non-blocked, by priorityScore DESC
  phases: {
    phase: 1 | 2 | 3;
    tasks: RoadmapTask[];
  }[];
  lastComputedAt: string;        // ISO 8601 — most recent UserRoadmapEntry.updatedAt
}

interface RoadmapTask {
  taskId: string;
  name: string;
  phase: number;
  status: TaskStatus;
  priorityScore: number;
  isBlocked: boolean;
  blockingTaskNames: string[];   // human-readable names of tasks blocking this one
  estimatedDuration: string;
  taskType: "FREE" | "PREMIUM";
  consequenceLine: string;       // from TaskContentVariant.consequenceLine for user's personaKey
}

// Error 404: { error: "PROFILE_NOT_FOUND", ... } if no UserProfile exists for user
// Error 404: { error: "ROADMAP_NOT_FOUND", ... } if no UserRoadmapEntry records exist
```

### Service: getRoadmap()

```typescript
// Steps:
// 1. Look up UserProfile for userId → 404 PROFILE_NOT_FOUND if missing
// 2. Fetch all UserRoadmapEntry for userId, joined with Task + TaskContentVariant (personaKey match)
// 3. Map each entry to RoadmapTask, resolving:
//    a. blockingTaskNames: look up Task.name for each blocking dep ID
//    b. consequenceLine: TaskContentVariant.consequenceLine for profile.personaKey
//       → fallback to solo_aewv variant if none found for user's personaKey
// 4. topThree = entries where status !== COMPLETE AND isBlocked === false,
//    sorted by priorityScore DESC, take first 3
// 5. phases = all entries grouped by task.phase, sorted by priorityScore DESC within each phase
// 6. lastComputedAt = most recent UserRoadmapEntry.updatedAt across all entries
```

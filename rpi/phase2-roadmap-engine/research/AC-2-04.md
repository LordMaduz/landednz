# Research: AC-2-04 — filterApplicableTasks() excludes school tasks for non-family

## Understanding

AC-2-04 requires implementing two pure functions in `apps/api/src/core/priority/filter.ts`:

1. **`filterApplicableTasks()`** — filters a task list to only those applicable to the user's
   profile. Each task has three JSON string fields (`applicableVisaTypes`,
   `applicableFamilySituations`, `applicableOccupations`) that must all pass against the user's
   profile values. `"ALL"` sentinel means no restriction on that dimension. Logic is AND across
   all three fields — a task is excluded if it fails any one.

2. **`derivePersonaKey()`** — maps the user's `familySituation` to a `PersonaKey` string used
   for scoring weights and KB retrieval. Derived from `familySituation` only — `visaType` is
   ignored for this mapping.

AC-2-04 verification: a task seeded with `applicableFamilySituations: '["FAMILY_WITH_CHILDREN"]'`
must be excluded when `filterApplicableTasks()` is called with a SOLO or COUPLE_CONSTRAINED profile.
Test uses constructed mock tasks (seed data not available until AC-2-15).

## Functions / Routes / Tests

### filterApplicableTasks()

```typescript
// Minimal Task interface — avoids importing Prisma in core/ (constitutional C02)
interface FilterableTask {
  id: string;
  applicableVisaTypes: string;      // JSON string — e.g. '["AEWV","PARTNER_OF_STUDENT"]' or '["ALL"]'
  applicableFamilySituations: string; // JSON string — e.g. '["FAMILY_WITH_CHILDREN"]' or '["ALL"]'
  applicableOccupations: string;    // JSON string — e.g. '["ALL"]'
  [key: string]: unknown;           // allow passthrough of other Task fields
}

interface TaskFilterInput {
  tasks: FilterableTask[];
  profile: {
    visaType: VisaType;
    familySituation: FamilySituation;
    occupation: Occupation;
  };
}

export function filterApplicableTasks(input: TaskFilterInput): FilterableTask[]
```

**Filtering rules:**
- Parse each JSON string field with `JSON.parse()`
- If parsed array includes `"ALL"` → field passes (no restriction)
- If parsed array includes the user's profile value → field passes
- All three fields must pass (AND logic)
- Malformed JSON → treat as `[]` → field fails → task excluded

### derivePersonaKey()

```typescript
export function derivePersonaKey(familySituation: FamilySituation): PersonaKey
```

**Mapping (exact — from priority-engine skill):**
- `COUPLE_CONSTRAINED` → `"constrained_couple"`
- `FAMILY_WITH_CHILDREN` → `"family_with_children"`
- all others (`SOLO`, `COUPLE_DUAL_WORK`) → `"solo_aewv"`

**Note:** `visaType` is NOT a parameter — only `familySituation` determines the persona key.

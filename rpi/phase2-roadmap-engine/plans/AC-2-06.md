## Approach

`GET /roadmap` is a read-only aggregation route. It fetches all `UserRoadmapEntry` records for the authenticated user in a **single Prisma query** with deep includes: the Task (name, phase, etc.), all TaskContentVariants (to resolve consequenceLine), and HARD TaskDependencies with prerequisite names (to resolve blockingTaskNames). No score recalculation occurs — scores are read as stored.

In code it then:
1. Builds a `completedTaskIds` set from entries with `status === COMPLETE`
2. Maps each entry to a `RoadmapTask` — resolves `consequenceLine` (personaKey → fallback solo_aewv → `''`) and `blockingTaskNames` (HARD deps where prerequisite not in completed set)
3. Selects `topThree`: filter `status !== COMPLETE AND isBlocked === false`, sort by `priorityScore` DESC, take 3
4. Groups all entries by `task.phase` for the `phases` array
5. Derives `lastComputedAt` from the most recent `updatedAt` across all entries

Tests use canonical task IDs (T06, T07, T08, T03) with correct basePriority values and the HARD dep T06→T07 so that `createProfile()` computes golden1 scores correctly before the roadmap is read.

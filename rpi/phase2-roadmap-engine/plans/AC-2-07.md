## Approach

`completeTask(userId, taskId, currentDate)` is added to `roadmap.service.ts`. It marks the `UserRoadmapEntry` as COMPLETE, calls `getAffectedTasks()` to find direct dependents, re-resolves `isBlocked` and rescores only those affected entries via `core/` functions (`resolveBlockedTasks()` + `scoreTask()`), then calls `getRoadmap(userId)` to get the updated topThree (reuses proven logic, no duplication). `unlockedTasks` = affected tasks that transitioned `isBlocked: true → false`. The route `POST /roadmap/tasks/:taskId/complete` is added to the existing `roadmap.route.ts`. `vitest.config.ts` gets `fileParallelism: false` to prevent concurrent DB task creation conflicts between integration test files that share canonical task IDs (T06/T07/T08/T03).

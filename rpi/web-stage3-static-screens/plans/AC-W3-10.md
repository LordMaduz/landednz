# Implementation Plan: AC-W3-10 — Auth Page (Google button, email expand, magic link sent, terms)

## Approach

Build the `/auth/signin` page as a centered card (max-width 420px, full-viewport height, no sidebar). The `AuthCard` client component implements a 4-state machine (`main | email | google_loading | magic_sent`) using `useState`. The page route (`(marketing)/auth/signin/page.tsx`) is a Server Component that renders the background, two decorative circles, and `<AuthCard />`. All buttons are native HTML `<button>` elements with Tailwind token classes — the Google button and "Continue with email" button use a custom grey-border outline style not in the `Button` UI primitive variants. The UI `Input` component is reused for the email field. No mock data needed — auth is UI-only state machine. No real OAuth or API calls (Stage 3 mock only; Stage 4 wires Supabase SSR).

Four new Tailwind tokens are added to `tailwind.config.ts` before writing any component:
- `maxWidth['auth-card']: '420px'`
- `boxShadow['auth-card']: '0 4px 24px rgba(26, 26, 46, 0.06)'`
- `fontSize['legal']: ['0.6875rem', { lineHeight: '1.5', fontWeight: '400' }]`
- `fontSize['h2-sm']: ['1.375rem', { lineHeight: '1.35', fontWeight: '400' }]`

All animations (`fade-in-up`, `fade-in`, `scale-in`) are already defined in globals.css under `@media (prefers-reduced-motion: no-preference)` — no globals.css changes needed.

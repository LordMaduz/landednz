# Research: AC-W3-13 — Playwright visual regression baselines captured at 1280 + 768

## Understanding

Create a Playwright visual regression test file that captures screenshot baselines for every
screen at 1280px and 768px. On first run with `--update-snapshots`, Playwright creates `.png`
baseline files. Subsequent `npx playwright test` runs compare against those baselines and pass
if visually identical (within configured threshold).

The AC passes when:
1. `e2e/visual.spec.ts` exists with `toHaveScreenshot()` calls for all 6 routes
2. Baselines are captured (files created in `e2e/visual.spec.ts-snapshots/`)
3. `npx playwright test --project=desktop-1280 --project=tablet-768` exits 0

**Generated by Playwright (not committed to review):**
- `apps/web/e2e/visual.spec.ts-snapshots/*.png` — the baseline images themselves

## Functions / Routes / Tests

**6 routes to capture:**

| Route | Auth needed | Viewport considerations |
|-------|-------------|------------------------|
| `/` | No | Full landing page — may need scroll to capture sections |
| `/onboarding` | No | Initial state (scope question) |
| `/auth/signin` | No | Default main state (Google + email) |
| `/roadmap` | Yes (sb-dev cookie) | Hero card + task list visible |
| `/chat` | Yes | Chat FAB closed state (overlay hidden by default) |
| `/settings` | Yes | Profile section visible |

**Test structure:**
- `test.beforeEach` sets auth cookie for app routes (matching existing pattern)
- `page.goto(route)` → `page.waitForLoadState('networkidle')` → `expect(page).toHaveScreenshot(name)`
- Separate `test.describe` blocks: marketing routes (no auth) and app routes (with auth)
- Snapshot names follow `[route]-[page].png` convention

**Viewport filtering:**
- The spec runs against ALL 5 projects by default
- AC requires only 1280 + 768 baselines — scope with `--project=desktop-1280 --project=tablet-768` on capture run
- OR add `project` filter in the config to only run visual regression on those two

**Preferred approach:** Run against all 5 projects (more coverage, same effort). The AC specifies minimum of 1280 + 768.

## Constraints That Apply

- **CW01** — no changes to component files, only test infrastructure

- Auth cookie: `{ name: 'sb-dev', value: '1', domain: 'localhost', path: '/' }` (same as layout.spec.ts)
- Fonts: DM Sans + DM Serif Display are self-hosted in `public/fonts/` — should load correctly

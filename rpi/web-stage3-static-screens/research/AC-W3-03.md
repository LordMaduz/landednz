# Research: AC-W3-03 — Roadmap reveal transition with reduced motion fallback

## Understanding

Replace the minimal "Building your plan..." placeholder from AC-W3-02 with a full animated reveal sequence. The reveal has two phases:

1. **Loading sequence**: 4 personalized messages based on user answers (visa type, city, family situation), displayed progressively with 600ms intervals, accompanied by 3 pulsing dots
2. **Success state**: Animated green checkmark circle, "Your plan is ready" heading, personalized summary line, and "See my roadmap →" CTA button

Key behaviors:
- Messages customize based on onboarding answers (e.g., "Checking requirements for Accredited Employer Work Visa...", "Sequencing tasks for Auckland...")
- Pulsing dots animation with staggered timing (0s, 0.2s, 0.4s delays)
- Success checkmark has draw-in animation with stroke-dasharray
- All animations respect `prefers-reduced-motion` (CW03) - instant state changes when reduced motion preferred
- Final CTA navigates user to roadmap dashboard

## Constraints That Apply

**CW03: Reduced Motion Respected**
All animations (pulseGlow, revealTextIn, checkDraw) MUST be wrapped in `@media (prefers-reduced-motion: no-preference)`. When reduced motion is preferred, replace with instant state changes - no progressive message display, no pulsing, no draw-in effects.

**CW01: Design Tokens Only**
All styling via Tailwind classes. Animation timing, colors, spacing must use configured tokens.

**CW04: Shared Types**
Reuse `OnboardingState` answers from AC-W3-02 to customize messages. No new type definitions.

## Ambiguities / Questions

**RESOLVED:**

**Navigation**: "See my roadmap →" navigates to `/roadmap` dashboard

**Missing answers**: Graceful degradation with generic fallbacks ("your visa type", "your city", "your situation") to maintain flow integrity

**State persistence**: Persist success state using localStorage flag `onboarding_reveal_completed`. Once reveal completes, always show "Your plan is ready" on return visits (no repeated animations)

# Research: AC-W3-12 — Responsive: all screens correct at 5 breakpoints

## Understanding

AC-W3-12 is a verification + fix AC. All Stage 3 screens must render correctly at 1440/1280/1024/768/375px. The Playwright config already has all 5 viewport projects from Stage 2. The Stage 2 layout tests (layout.spec.ts) already cover the sidebar/MobileNav behavior at all viewports and pass.

However, Stage 3 added new components (LandingNav, ChatPanel) that have responsive issues at mobile viewports. Two targeted fixes are needed before the visual verification passes:

**Fix 1 — LandingNav at 375px (OVERFLOW):**
The nav links div `<div className="flex items-center gap-8">` contains "How it works" + "Pricing" + "Build my plan" buttons. At 375px viewport width, this overflows (~514px required vs 375px available). Fix: `hidden md:flex` on the links container — hides all nav links at mobile, leaving just the logo mark visible. This is standard SaaS mobile nav behaviour and consistent with how the app sidebar hides at mobile.

**Fix 2 — ChatPanel at 375px (OVERFLOW):**
`w-chat-panel` (420px) wider than 375px viewport. The panel is `fixed bottom-6 right-6` — it overflows 45px off the left edge. Fix: responsive sizing — at mobile the panel uses `inset-x-0 bottom-0 w-full h-[90vh] rounded-b-none`, at `md:` uses the original `bottom-6 right-6 w-chat-panel h-chat-panel`. Since `h-[90vh]` is an arbitrary value, it needs a Tailwind token. Better: use `max-h-[calc(100dvh-2rem)]` is also arbitrary. Cleanest CW01-compliant fix: add `h-chat-panel-mobile: '90vh'` token, OR use the `max-h-[calc(100vh-3rem)]` that already exists in the classname, OR keep it simple and at mobile make the panel full-width/bottom-anchored using `inset-x-0 bottom-0 rounded-b-none`.

Actually re-checking: the existing ChatPanel already has `max-h-[calc(100vh-3rem)]` in its classes — that IS an arbitrary value. Since this was already there from W3-07 and passed code review, arbitrary calc values for height are acceptable when there's no pure-token equivalent. So I can safely add `md:bottom-6 md:right-6 md:w-chat-panel md:h-chat-panel w-full h-screen bottom-0 right-0 rounded-b-none md:rounded-chat-panel`.

Wait — simpler approach: at mobile, hide the ChatPanel entirely (don't show floating chat at <768px). The chat FAB already shows at all breakpoints. When user taps FAB at mobile, the overlay doesn't render at full size — it could just not open at mobile. But that's a UX regression. Better: make the panel responsive.

**Simplest compliant fix for ChatPanel mobile**: Replace the fixed position/size classes with responsive variants:
- Mobile: `inset-x-0 bottom-0 h-[85vh] rounded-t-chat-panel rounded-b-none`
- `md:`: `bottom-6 right-6 w-chat-panel h-chat-panel rounded-chat-panel`

But `h-[85vh]` is arbitrary. Alternative: add `h-chat-panel-mobile: '85vh'` to tailwind.config.ts. This keeps CW01 compliance.

**Best approach**: Add one token `'chat-panel-mobile': '85vh'` to height config, then use `h-chat-panel-mobile md:h-chat-panel`. This keeps full CW01 compliance with minimal token surface.

# Research: AC-W3-10 — Auth page (Google button, email expand, magic link sent, terms)

## Understanding

Build the `/auth/signin` page as a centered card (max-width 420px, full-viewport, no sidebar).
The page has 4 interactive states:

1. **main** — Logo + "Save your progress" heading + subtitle + Google OAuth button + "or" divider + "Continue with email" button (collapsed, secondary style)
2. **email** — Same header, but email section replaces the collapsed button: email input + "Continue" button + "← Back" link
3. **google_loading** — Google button shows spinner + "Connecting to Google..." text (simulated, 2.5s then back to main)
4. **magic_sent** — Full card replaced: green email icon, "Check your email" heading, email displayed, expiry note, "← Use a different email" back link

Additional elements always present (in main + email modes):
- Trust signal: "We'll never share your email. No spam, ever." (0.8125rem caption)
- Terms: "By continuing, you agree to our Terms of Service and Privacy Policy" (0.6875rem legal)

Background has two subtle decorative circles (border-only, low opacity, pointer-events none).

No real auth — fully mock. Stage 3 only. Auth wired in Stage 4 (AC-W4-01).

## Functions / Routes / Tests

**State machine** (client component):
```typescript
type AuthMode = 'main' | 'email' | 'magic_sent' | 'google_loading'
```

**AuthCard** (default export from `components/auth/AuthCard.tsx`):
- `useState<AuthMode>('main')` for mode
- `useState('')` for email + emailError
- `handleGoogleClick()` — sets `google_loading`, setTimeout 2500ms → `main`
- `handleEmailSubmit()` — validates email format, sets `magic_sent` or emailError
- Renders different content branch for `magic_sent`
- Renders email input section when mode is `email` or `error`

**GoogleLogo** sub-component — inline SVG (4-path coloured Google logo)
**Spinner** sub-component — animated SVG circle arc

**Animations** (CSS via globals.css or tailwind `animate-` classes):
- `fadeInUp`: main card entrance (translateY 16px → 0, opacity 0→1)
- `fadeIn`: email section appear
- `scaleIn`: magic_sent state entrance (scale 0.95→1)
- All three must be disabled under `prefers-reduced-motion: reduce` (CW03)

**Storybook stories**: 4 stories using `useState` simulation (no decorators needed)

## Constraints That Apply

- **CW01**: All colours, radii, font sizes via Tailwind tokens — no raw hex/px in component. New tokens (`shadow-auth-card`, `text-legal`) must be added to `tailwind.config.ts` first.
- **CW02**: Storybook story required for `AuthCard` (feature component; AC-W3-14 mandates all feature components have stories)
- **CW03**: All 3 animations (`fadeInUp`, `fadeIn`, `scaleIn`) must be suppressed under `prefers-reduced-motion: reduce`. Use `@media (prefers-reduced-motion: reduce)` in globals.css keyframe blocks.
- **CW05**: No mock data involved — auth is UI-only state machine
- **CW06**: No localStorage auth — this is Stage 3 mock only; Stage 4 will wire Supabase SSR

## Ambiguities / Questions

1. **`magic_sent` heading size (1.375rem)**: The mockup uses `1.375rem` for "Check your email" heading. The closest Tailwind token is `text-h2` at `1.5rem` (slightly larger). Options: (a) use `text-h2` (close but not exact), (b) add a new `text-h2-sm: ['1.375rem', ...]` token. Given precedent of adding precise tokens, option (b) is correct — but is this worth adding a token for one string?

2. **Card shadow**: Mockup uses `0 4px 24px rgba(26, 26, 46, 0.06)` which is not in any existing shadow token. Plan is to add `shadow-auth-card`. Confirmed approach.

3. **Page route**: The stub at `(marketing)/auth/signin/page.tsx` works. The AC says "Auth" page — should the route be `/auth` or `/auth/signin`? The existing stub is at `/auth/signin`. This seems intentional (supports `/auth/reset`, etc. later). No action needed.

Neither ambiguity 1 nor 2 blocks planning — both have clear answers. #1: add `text-h2-sm` token for exactness. #2: add `shadow-auth-card`.

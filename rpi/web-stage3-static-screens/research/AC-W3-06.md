# Research: AC-W3-06 — Task detail view (content replacement pattern)

## Understanding

Clicking any task row replaces the roadmap list in the content area with a `TaskDetail`
component. The sidebar stays mounted. No right panel, no third column. This is the
Linear pattern already locked in the spec and enforced since Stage 2.

The detail view has 7 sections:
1. **Back button** — arrow left + "Back to roadmap" in primary colour
2. **Task header** — large DM Serif Display title + Phase/Time/Difficulty badges
3. **Consequence callout** — amber left-border box: "Why this matters now" + body text
4. **Steps list** — numbered circles connected by vertical lines
5. **Documents needed** — required (filled dot) vs optional (empty dot) items
6. **Official source card** — agency + page label + "Go to ird.govt.nz" button (success-light bg)
7. **Helpful tips** — collapsible section with ChevronRight toggle

Below those: **"Ask a question about this task"** button (full-width outline, links to chat entry point) and **two action buttons**: "Mark as done" (primary) + "I've already done this" (outline).

**Animation**: slideInRight (translateX 20px → 0, 0.3s ease-out). Instant when `prefers-reduced-motion`.

## Constraints That Apply

- **Critical design decision #1 (REQUEST.md)**: Task detail REPLACES list view — NOT a right panel. Failure to follow this is a known failure point.
- **CW01**: No arbitrary values
  - `border-l-3` ✅ already defined in tailwind.config.ts
  - Consequence callout right-side rounding: need `rounded-r-button` (10px) — check if token exists, add if not
  - Connector line `absolute left-[13px]` is an arbitrary value — use `left-3.5` (14px, close enough) or add custom token
- **CW03**: `slideInRight` animation must be inside `prefers-reduced-motion: no-preference` media query — use `motion-reduce:transform-none motion-reduce:transition-none`
- **CW05**: `TaskDetailData` added to `TaskListItem` must match what the API will eventually return

## Ambiguities / Questions

1. **`rounded-r-button` token**: The consequence callout needs right-only rounding at 10px. Does a `rounded-r-button` class exist? If not, should we add it to tailwind.config.ts, or use `rounded-r-lg` (8px) as the closest existing token?
2. **Connector line position**: The mockup uses `left-[13px]` (half of 28px number circle = 14px). Closest Tailwind default is `left-3.5` (14px) which is correct.
3. **"Ask a question" button**: Opens chat. In Stage 3 (mock), is this a no-op button or should it navigate? Per REQUEST.md scope, we don't wire real chat — stub with `onClick={() => {}}` and comment "// Chat entry point wired in AC-W4-10".
4. **Action buttons**: "Mark as done" and "I've already done this" — both are stubs in Stage 3 (no API). Comment: "// Task completion wired in AC-W4-08".

None of these block planning — all have clear resolutions within the constraints.

## Ready to Plan

**YES** — no blocking ambiguities. All 4 questions have clear answers within the spec.

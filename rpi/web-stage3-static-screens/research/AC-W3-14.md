# Research: AC-W3-14 — All feature components in Storybook, zero console errors

## Understanding

AC-W3-14 requires every feature component built across Stage 3 (and Stage 2 layout components) to have at least one Storybook story, and `npm run storybook` must produce zero console errors. This is a coverage audit + cleanup pass: no new components to build, only stories to write and any console errors to fix.

The AC intentionally ships last (before AC-W3-15) so all components are stable before stories are written.

## Functions / Routes / Tests

- No new component logic — stories only
- Verification: `npm run storybook` → open browser → check console for errors on every story
- Each story must render without runtime errors, broken imports, or missing mock data

## Constraints That Apply

- **CW01** — story `args` and decorators must use design token classes only, no raw hex/px
- **CW02** — this AC IS the CW02 enforcement pass for Stage 3 feature components
- **CW05** — any mock data used in stories must conform to `@landednz/types` interfaces (same shape as API)
- **'use client'** — `LandingHero` has `'use client'` directive due to onClick scroll handler; Storybook uses Vite + react-vite framework so this is compatible, but worth verifying no SSR issues

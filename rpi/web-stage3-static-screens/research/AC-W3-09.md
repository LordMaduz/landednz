# Research: AC-W3-09 — Settings screen

## Understanding

Build the Settings page at `/settings` with four section cards: Profile, Subscription, Notifications, Account. The existing route stub (`settings/page.tsx`) is replaced with a full `SettingsView` component.

### Section breakdown (from mockup):

**Profile**
- `FieldRow` for Name (editable) + Email (with "Managed by Google" badge, no edit)
- "Your onboarding answers" sub-header
- 2-column grid of `FieldRow` items: Visa type, City, Settling with, Occupation, Arrival (all editable in mockup — mock handlers in Stage 3)
- Italic helper text: "Changing your answers will update your roadmap to match."

**Subscription**
- `FieldRow`-style row: "Free" plan label + "Phase 1 & 2 only" muted badge
- Teal gradient upgrade banner: copy + "Upgrade" button (amber `bg-secondary`)

**Notifications**
- "Email reminders" toggle row with descriptive sub-text
- When toggle ON: reveal "Reminder frequency" radio options (2 options: "Before deadlines only" / "Weekly progress summary")
- Italic anti-spam note below radio options

**Account**
- Full-width outline "Sign out" button (with sign-out SVG icon)
- Divider + "Delete account" danger link (smaller, tertiary color → error on hover)
- Clicking opens `DeleteModal`

**DeleteModal**
- Fixed overlay: semi-transparent backdrop + blur
- 420px white card, 14px radius, shadow-modal
- 48px error-light circle with warning SVG
- Heading + body copy + Cancel + "Delete my account" (error bg) buttons
- scaleIn + fadeIn animations

## Constraints That Apply

**CW01 (Design Tokens):** No raw hex in components. Subscription gradient needs `bg-subscription-gradient` token. Toggle shadow needs `shadow-toggle` token. Modal backdrop uses `bg-text-primary/40` (opacity modifier).

**CW02 (Storybook Required):** `SettingsView.stories.tsx` covers default, notifications-off, and delete-modal-open states.

**CW03 (Reduced Motion):** Delete modal `scaleIn`/`fadeIn` animations use `fade-in` + `scale-in` CSS classes (from globals.css, inside `@media no-preference` guard). No Tailwind arbitrary animation values.

**CW04 (Shared Types):** Mock data shape matches `OnboardingState.answers` structure from `@/types/web.ts`. No new shared types needed.

**CW05 (Mock Data Shape):** `MOCK_PROFILE` and `MOCK_ONBOARDING_ANSWERS` in `src/mocks/settings.ts` must match the shape that Stage 4 API will return.

**CW06 (No localStorage Auth):** Sign out and delete account are mock handlers (`() => {}`) in Stage 3. No localStorage writes.

### Step 3 — Implement buildChatSystemPrompt() in registry.ts (GREEN)
Full 7-component implementation (pure function — zero DB/framework imports, C02):

**Signature:**
```typescript
export function buildChatSystemPrompt(params: BuildSystemPromptParams): string
```

**Component order (non-negotiable, C06):**
1. **Identity** (~150 tokens) — fixed text defining LandedNZ role, what it is/isn't
2. **User profile injection** (~300–500 tokens) — name, visa, family, city, occupation, arrivalDaysAgo, recent completions (last 5), conditional task context for TASK_CARD/EMAIL_DEEPLINK only. COUPLE_CONSTRAINED gets partner visa + 20hr work limit block.
3. **Persona anchor TOP** (~60 tokens) — "PERSONA ANCHOR — READ BEFORE EVERY RESPONSE: You are speaking with [name]..."
4. **Behavioural constraints** (~400 tokens) — 8 rules (GROUNDING, SPECIFICITY, CITATION, UNCERTAINTY, PERSONA CONSISTENCY, SCOPE, EMOTIONAL SIGNALS, NEVER FABRICATE). Guardrail augmentations appended after rule 8 if non-empty.
5. **Scope boundaries** (~500 tokens) — IN SCOPE, BOUNDARY CASES, OUT OF SCOPE tiers with redirect format rules
6. **Retrieved KB chunks** (~900–1,500 tokens) — Phase 4 placeholder: task content variants formatted as `[CHUNK N — {chunkKey} — {personaKey}]\n{content}\nSource: {sourceName} — {sourceUrl}`
7. **Persona anchor BOTTOM** (~60 tokens) — "FINAL REMINDER: You are speaking with [name]..."

Target: 2,370–3,320 tokens. Hard ceiling: 3,500 tokens.

### Step 8 — Implement sendMessage() in service.ts (GREEN)
10-step pipeline (exact C06 order — Level 1 at step 2, Level 2 at step 9):

```
1.  db.chatMessage.create({ role: 'USER', content, sessionId })
2.  runLevel1Guardrail(content) → { flags, augmentations }
3.  db.chatMessage.findMany({ where: { sessionId }, orderBy: { createdAt: 'asc' } }) → history
4.  db.taskContentVariant.findMany for session.taskContext → format as ChatKbChunk[]
5.  buildChatSystemPrompt({ user, entryPoint, taskName, kbChunks, guardrailAugmentations })
6.  streamMessage(systemPrompt, historyMessages, onChunk)
7.  onChunk writes: rawReply.write('data: ' + JSON.stringify({ type: 'chunk', text }) + '\n\n')
8.  db.chatMessage.create({ role: 'ASSISTANT', content: fullResponse, guardrailFlags, retrievedChunks })
9.  runLevel2Guardrail(fullResponse) → db.chatMessage.update({ level2Flags })
10. rawReply.write('data: ' + JSON.stringify({ type: 'done' }) + '\n\n') + rawReply.end()
```

AIFailureError handling: catch inside pipeline → `rawReply.write(error event)` → `rawReply.end()`. Never propagates to global handler (C13).

Session ownership check: verify `session.userId === userId` → 403 if mismatch.

### Step 9 — Add messages route to routes.ts

```typescript
app.post<{ Params: { sessionId: string }; Body: SendMessageRequest }>(
  '/chat/sessions/:sessionId/messages',
  { preHandler: authenticateRequest },
  async (request, reply) => {
    if (!request.body.content) {
      throw new AppError('VALIDATION_ERROR', 'Missing required field: content', 400)
    }
    reply.raw.setTimeout(0)  // prevent Railway 30s timeout
    reply.raw.writeHead(200, {
      'Content-Type': 'text/event-stream',
      'Cache-Control': 'no-cache',
    })
    await sendMessage(request.userId, request.params.sessionId, request.body.content, reply.raw)
  },
)
```

## Test Strategy

AC-4-02 verification via `messages.test.ts` integration test:
1. Create test user + subscription + profile + chat session in `beforeAll`
2. POST to `/chat/sessions/:sessionId/messages` with `{ content: "What documents do I need for my IRD application?" }`
3. Receive full SSE body via `app.inject()`
4. Parse: split on `\n\n`, filter non-empty, strip `data: ` prefix, `JSON.parse` each
5. Assert every event has `type === 'chunk'` or `type === 'done'`
6. Assert at least 1 `chunk` event
7. Assert exactly 1 `done` event, and it is last
8. Assert concatenated chunk texts form a non-empty response string

Test uses real Anthropic API (`ANTHROPIC_API_KEY` in `.env.test.local`) and real DB (consistent with all Phase 2/4 integration tests).

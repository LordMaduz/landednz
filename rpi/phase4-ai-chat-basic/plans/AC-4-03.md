# Implementation Plan: AC-4-03

## Approach
AC-4-03 verifies SSE chunks arrive progressively (not buffered). The existing
`service.ts` already uses `reply.raw.write()` per chunk and `reply.raw.setTimeout(0)`.
Two small gaps remain: (1) the `writeHead()` call is missing `Connection: keep-alive`
and `X-Accel-Buffering: no` headers which are required for HTTP/1.1 SSE non-buffering
through proxies; (2) there is no automated progressive-delivery verification because
`app.inject()` buffers responses and cannot prove chunk-by-chunk delivery. The plan
adds the two headers and creates a standalone verification script using Node.js native
`fetch()` with `ReadableStream` that connects to the real running server.

## File Changes
1. **Modify** `apps/api/src/features/chat/service.ts`
   - In `sendMessage()`, update `reply.raw.writeHead(200, {...})` to include:
     `'Connection': 'keep-alive'` and `'X-Accel-Buffering': 'no'`

2. **Create** `apps/api/scripts/test-sse-streaming.ts`
   - Standalone Node.js script (not a vitest test)
   - Signs in via Supabase auth API to get a real JWT
   - Creates a chat session via POST /chat/sessions
   - POSTs a message to POST /chat/sessions/:id/messages
   - Reads the response as a ReadableStream using `response.body.getReader()`
   - Logs each chunk with its arrival timestamp (ms)
   - Asserts: at least 1 chunk event arrives, stream ends with `done` event
   - Exits with code 0 on success, code 1 on failure

## Implementation Order
1. Update `writeHead()` in `service.ts` — add 2 headers (1-line change)

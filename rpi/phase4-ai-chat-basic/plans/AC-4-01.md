# Implementation Plan: AC-4-01

## Approach

TDD from pure functions outward. Start with `buildChatOpeningMessage()` in `core/prompts/registry.ts`
(pure function, zero dependencies — easiest to test in isolation). Then build the `createChatSession()`
service (DB + pure function composition). Then the route (auth + subscription gate + service call).
AC-4-13 (subscription 403) is implemented on the same route — no separate step.

The opening message for TASK_CARD requires the task name, so the service fetches the Task record by
`taskContext` ID. `buildChatOpeningMessage()` receives `{ taskName }` — it does NOT touch DB.
`buildChatSystemPrompt()` is stubbed with `throw new Error('TODO: AC-4-08')` to enforce the
registry-only constraint for future ACs without requiring full implementation now.

## Implementation Order

1. **Write failing tests** in `registry.test.ts`:
   - `buildChatOpeningMessage()` TASK_CARD → contains task name, no generic greeting
   - `buildChatOpeningMessage()` ROADMAP → contains completion count and city
   - `buildChatOpeningMessage()` EMAIL_DEEPLINK → same as TASK_CARD
   - `buildChatOpeningMessage()` NAVIGATION → same as ROADMAP

2. **Implement `buildChatOpeningMessage()`** in `registry.ts` — pure function, no imports beyond types:
   ```typescript
   // TASK_CARD / EMAIL_DEEPLINK:
   // "You're looking at the [taskName] task. I know you're [persona context]. What would you like to know?"

   // ROADMAP / NAVIGATION:
   // "Hi [name] — you've completed [completedTaskCount] tasks so far.
   //  What would you like to know about settling in [city]?"
   ```
   Add stub: `export function buildChatSystemPrompt(...): string { throw new Error('TODO: AC-4-08') }`

3. **Verify registry tests pass.**

4. **Create `chat.types.ts`**:
   ```typescript
   import type { ChatEntryPoint } from '@landednz/types'
   export interface CreateSessionRequest { entryPoint: ChatEntryPoint; taskContext?: string }
   export interface CreateSessionResponse { sessionId: string; openingMessage: string }
   ```

5. **Create `service.ts`** — `createChatSession()`:
   - Fetch `UserProfile` + count completed `UserRoadmapEntry` where `status === 'COMPLETE'`
   - If `TASK_CARD` or `EMAIL_DEEPLINK`: fetch `Task` by `taskContext` ID → `AppError('TASK_NOT_FOUND', ..., 404)` if missing
   - Create `ChatSession` record in DB
   - Call `buildChatOpeningMessage()` with assembled data
   - Return `{ sessionId, openingMessage }`

6. **Create `routes.ts`** — `registerChatRoutes()`:
   - `preHandler: [authenticateRequest]` on all routes
   - `POST /chat/sessions`:
     - Subscription check: `db.subscription.findUnique({ where: { userId } })` → 403 `SUBSCRIPTION_REQUIRED` if `!sub?.isActive`
     - Call `createChatSession()`
     - Reply 201

7. **Register routes** in `server.ts`:
   ```typescript
   import { registerChatRoutes } from './features/chat/routes'
   // inside buildApp():
   registerChatRoutes(app)
   ```

8. **Write integration tests** in `service.test.ts` or `routes.test.ts`:
   - Subscribed user + TASK_CARD T08 → 201, `openingMessage` contains "IRD" or "tax" (AC-4-01 verification)
   - Unsubscribed user → 403 (AC-4-13 verification)
   - TASK_CARD with unknown taskContext → 404
   - ROADMAP entry point → 201, openingMessage contains completion count

9. **Run `npx tsc --noEmit`** — zero errors required before commit.

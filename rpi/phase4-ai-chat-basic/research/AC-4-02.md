# Research: AC-4-02 — POST /chat/sessions/:sessionId/messages streams valid SSE events

## Understanding

`POST /chat/sessions/:sessionId/messages` is the core SSE streaming endpoint. It accepts
a user message, runs it through the 10-step pipeline (persist → Level 1 guardrail →
history → task content → system prompt → streamMessage() → write chunks → persist
assistant message → Level 2 guardrail → close stream), and delivers the response as
`text/event-stream` events to the client.

The AC-4-02 verification is: **consume full SSE stream and reconstruct complete response**.
Each event must be valid JSON with `type: "chunk"` or `type: "done"`.

This AC requires creating `shared/ai/claude.client.ts` (the only Anthropic SDK import point),
adding the messages route to `routes.ts`, implementing `sendMessage()` in `service.ts`, and
creating guardrail stubs for `level1.ts` and `level2.ts`. `buildChatSystemPrompt()` will be
implemented with all 7 components, dynamic user profile injection, and persona anchors.
AC-4-08 becomes a verification-only test of the token count and component structure.

## Functions / Routes / Tests

**Route:** `POST /chat/sessions/:sessionId/messages`
- Auth middleware (existing `shared/middleware/auth.ts`)
- Params: `{ sessionId: string }`
- Body: `{ content: string }`
- Verify session belongs to `request.userId` (404 if not found, 403 if wrong user)
- Use `reply.raw` for SSE (C14) — never `reply.send()`
- `reply.raw.setTimeout(0)` required (prevents Railway 30s timeout)
- Call `sendMessage(userId, sessionId, content, reply.raw)`

**Service: `sendMessage()`** — 10-step pipeline (C06):
```
1.  db.chatMessage.create({ role: USER, content })
2.  runLevel1Guardrail(content) → guardrailAugmentations[]
3.  db.chatMessage.findMany({ sessionId, orderBy: createdAt asc })
4.  db.taskContentVariant.findMany({ task: { id: session.taskContext } })  ← Phase 4 RAG placeholder
5.  buildChatSystemPrompt(userProfile, task, guardrailAugmentations) from registry.ts
6.  claude.streamMessage(systemPrompt, history, onChunk)
7.  onChunk: reply.raw.write(`data: ${JSON.stringify({ type: 'chunk', text })}\n\n`)
8.  db.chatMessage.create({ role: ASSISTANT, content: fullResponse, guardrailFlags, retrievedChunks })
9.  runLevel2Guardrail(fullResponse) → level2Flags — update message with flags
10. reply.raw.write(`data: ${JSON.stringify({ type: 'done' })}\n\n`) + reply.raw.end()
```

AIFailureError handling: caught inside sendMessage(), emits `{ type: 'error', message: 'AI service unavailable' }` SSE event before `reply.raw.end()` (never propagates to global handler per C13).

**`streamMessage()` in `shared/ai/claude.client.ts`:**
```typescript
export async function streamMessage(
  systemPrompt: string,
  messages: ChatMessage[],
  onChunk: (text: string) => void,
): Promise<void>
```
- `model: process.env.ANTHROPIC_MODEL` (never hardcode)
- `max_tokens: 1024` (never increase)
- SDK stream events: check `event.type === 'error'` → throw `AIFailureError`
- Wrap entire SDK call in try/catch → convert to `AIFailureError`

**`buildChatSystemPrompt()` in `core/prompts/registry.ts`:**
Full implementation with all 7 components in exact order:
1. Identity (~150 tokens)
2. User profile injection with dynamic family situation logic (~300–500 tokens)
3. Persona anchor TOP (~60 tokens)
4. Behavioural constraints + Level 1 guardrail augmentations (~400 tokens)
5. Scope boundaries (~500 tokens)
6. Retrieved KB chunks - Phase 4 placeholder: task content variants (~900–1,500 tokens)
7. Persona anchor BOTTOM (~60 tokens)

Target: 2,370–3,320 tokens. Hard ceiling: 3,500 tokens.

## Constraints That Apply

- **C03 (SDK isolation):** `@anthropic-ai/sdk` imported ONLY in `shared/ai/claude.client.ts`. No other file.
- **C04 (registry only):** All prompt strings constructed in `core/prompts/registry.ts`. No inline strings in service or route.
- **C06 (SSE pipeline order):** Level 1 at step 2 (before prompt construction). Level 2 at step 9 (after persist). Order is non-negotiable.
- **C13 (error hierarchy):** `AIFailureError` caught INSIDE `sendMessage()`, never reaches global handler. Emitted as SSE error event.
- **C14 (SSE uses reply.raw):** `reply.raw.setTimeout(0)` + `reply.raw.writeHead()` + `reply.raw.write()` + `reply.raw.end()`. Never `reply.send()`.
- **Known gotcha:** Global error handler does NOT catch errors after headers sent — must catch inside `reply.raw.write()` loop.

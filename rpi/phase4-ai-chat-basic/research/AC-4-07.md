# Research: AC-4-07 — Level 2 MISSING_CITATION guardrail

## Understanding

Implement `runLevel2Guardrail()` in `level2.ts` — currently a stub returning empty flags.
Level 2 is an OUTPUT validator that runs on the COMPLETE assistant response AFTER it is
persisted (step 9 of the SSE pipeline). It is LOGGING ONLY — never blocks or modifies
the response.

AC-4-07 specifically requires: when the response lacks `"Source:"` followed by a URL,
the `MISSING_CITATION` flag fires and gets stored in `ChatMessage.level2Flags`.

The DB storage pipeline is already wired in `service.ts` (steps 9–10 from AC-4-02):
```typescript
const level2Result = runLevel2Guardrail(fullResponse);
if (level2Result.flags.length > 0) {
  await db.chatMessage.update({ where: { id }, data: { level2Flags: JSON.stringify(...) } });
}
```

So implementing `runLevel2Guardrail()` to return real flags is all that's needed for the
DB storage to work — no service.ts changes required.

**Scope decision:** Implement MISSING_CITATION (required by AC) and SPECIFIC_NUMBER
(simple, no ambiguity). Leave POTENTIAL_OUT_OF_SCOPE as a documented stub to avoid false
positives that would degrade UX for human reviewers — most settlement responses don't
contain redirect URLs, so any heuristic would flag legitimate responses incorrectly.

## Functions / Routes / Tests

**level2.ts implementation:**

```typescript
export function runLevel2Guardrail(response: string): Level2Result {
  const flags: string[] = [];

  // MISSING_CITATION: response must contain "Source:" followed by a URL anywhere after
  const sourceIndex = response.indexOf('Source:');
  const hasCitation = sourceIndex !== -1 && /https?:\/\//.test(response.slice(sourceIndex));
  if (!hasCitation) {
    flags.push('MISSING_CITATION');
  }

  // SPECIFIC_NUMBER: response contains %, $, NZD, or "working days" time patterns
  if (/%|\$|NZD|working days/.test(response)) {
    flags.push('SPECIFIC_NUMBER');
  }

  // POTENTIAL_OUT_OF_SCOPE: documented stub — implementation requires Level 1 flags
  // to avoid false positives. Most settlement responses don't contain redirect URLs.

  return { flags };
}
```

**level2.test.ts tests:**

MISSING_CITATION:
- Response without "Source:" → MISSING_CITATION fires
- Response with "Source: https://ird.govt.nz" → does NOT fire
- Response with "Source:" but no URL → fires (e.g., "Source: see website")
- Empty response → fires

SPECIFIC_NUMBER:
- Response with "%" → SPECIFIC_NUMBER fires
- Response with "$" → fires
- Response with "NZD" → fires
- Response with "working days" → fires
- Normal response without numbers → does NOT fire

## Ambiguities / Questions

**Resolved during research session:**

1. **POTENTIAL_OUT_OF_SCOPE implementation scope** — **Decision: Option A (documented stub).**
   Implementing a heuristic without Level 1 context would create false positives (most settlement
   responses don't contain redirect URLs), degrading UX for human reviewers. Leave as documented
   stub until Level 1 flags can be passed to the function. Prioritizes clean logs over
   feature completeness. ✓

2. **"Source:" URL detection strictness** — **Decision: URL anywhere after "Source:" in string.**
   More forgiving of formatting differences while still requiring both "Source:" and URL.
   Better UX than strict same-line requirement. Implementation: check for `https?://` pattern
   anywhere in `response.slice(sourceIndex)` after finding "Source:". ✓

# Research: AC-4-01 — POST /chat/sessions creates session + entry-point-specific opening message

## Understanding

`POST /chat/sessions` creates a `ChatSession` record and returns a contextual opening message
built by `buildChatOpeningMessage()` in `core/prompts/registry.ts`. The opening message is
**not a Claude API call** — it is static text constructed from user profile data and the entry
point. For TASK_CARD, it must reference the task name (requires a DB fetch of the task by taskContext ID).
For ROADMAP/NAVIGATION, it references the completed task count.

Verification test: TASK_CARD with taskContext "T08" → opening message mentions "IRD" or "tax".
This passes only if the route correctly fetches T08's task name and passes it to buildChatOpeningMessage().

AC-4-13 (subscription gate) affects this same route — 403 if user has no active subscription.
Implementing both together is the right approach — no separate work needed.

## Functions / Routes / Tests

**Route:** `POST /chat/sessions`
- Auth middleware (existing `shared/middleware/auth.ts`)
- Subscription gate: `db.subscription.findUnique({ where: { userId } })` → 403 if `!isActive`
- Body: `{ entryPoint: ChatEntryPoint, taskContext?: string }`
- Calls `createChatSession(userId, entryPoint, taskContext)`
- Returns 201 `{ sessionId, openingMessage }`

**Service: `createChatSession()`**
1. Fetch user profile + completed task count from DB
2. If `entryPoint === TASK_CARD`, fetch task by `taskContext` ID to get task name
3. Create `ChatSession` record in DB
4. Call `buildChatOpeningMessage(entryPoint, user, taskContext)` → opening message string
5. Return `{ sessionId, openingMessage }`

**`buildChatOpeningMessage()` in `core/prompts/registry.ts`:**
```typescript
export function buildChatOpeningMessage(
  entryPoint: ChatEntryPoint,
  user: { name: string | null; profile: UserProfile; completedTaskCount: number },
  taskContext: { taskName: string } | null,
): string
```
- TASK_CARD / EMAIL_DEEPLINK → references task name + persona-specific context
- ROADMAP / NAVIGATION → references user name + completed task count + city

**Tests required (TDD — write first):**
- `buildChatOpeningMessage()` TASK_CARD with T08 context → output contains "IRD" or "tax"
- `buildChatOpeningMessage()` ROADMAP → output contains completion count
- `buildChatOpeningMessage()` TASK_CARD → output does NOT contain generic "Hi! How can I help?"
- `POST /chat/sessions` integration: subscribed user + TASK_CARD T08 → 201, openingMessage mentions IRD
- `POST /chat/sessions` integration: unsubscribed user → 403

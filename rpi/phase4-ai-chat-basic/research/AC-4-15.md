# Research: AC-4-15 — ChatMessage persisted both roles, retrievedChunks + guardrailFlags populated

## Understanding

This is a **verification-only AC**. The persistence logic is already implemented in `service.ts` from AC-4-02. The AC requires a test that proves — by querying the DB after a message exchange — that:

1. Both USER and ASSISTANT ChatMessage records exist in the DB after a message is processed
2. The ASSISTANT ChatMessage has `retrievedChunks` populated (non-empty JSON array of chunk keys when task context is set)
3. The ASSISTANT ChatMessage has `guardrailFlags` populated when a Level 1 flag triggers (e.g., CRISIS_SIGNAL)
4. The ASSISTANT ChatMessage has `guardrailFlags` as `"[]"` when no Level 1 flags trigger

The implementation in `service.ts` already handles this correctly:
- Step 1: `db.chatMessage.create({ role: 'USER', content, sessionId })` — user message persisted
- Step 8: `db.chatMessage.create({ role: 'ASSISTANT', content: fullResponse, guardrailFlags: JSON.stringify(level1Result.flags), retrievedChunks: JSON.stringify(kbChunks.map(chunk => chunk.chunkKey)) })` — assistant message with both fields
- Step 9: `db.chatMessage.update({ level2Flags: ... })` — level2 flags added if triggered

`guardrailFlags` on the ASSISTANT message stores the Level 1 flags that affected that response (correct placement — flags affect how the response was augmented). The USER message has no guardrailFlags, which is by design.

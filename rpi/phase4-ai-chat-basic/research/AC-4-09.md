## Understanding

validated at a structural level by AC-4-08 (component order). AC-4-09 specifically asserts
that the five user fields — name, visaType, familySituation, city, arrivalDaysAgo — are

test('AC-4-09: COUPLE_CONSTRAINED user — all 5 profile fields injected correctly', () => {
  const result = buildChatSystemPrompt(mockSystemPromptParams); // familySituation: COUPLE_CONSTRAINED

  // All 5 required fields

## One Discrepancy Noted

The spec signature shows `arrivalDaysAgo: number | null` (null if pre-arrival), but
`chat.types.ts` defines `arrivalDaysAgo: number` (non-nullable). The current implementation
renders `"null days ago"` for a pre-arrival user (no null guard in registry.ts line 91).

**This is NOT in scope for AC-4-09** — the AC only tests an already-arrived
COUPLE_CONSTRAINED user. Flag it as a gotcha for AC-4-15 (ChatMessage persistence) when
the full service wires real user data.

# Research: AC-4-11 — AIFailureError → SSE error event, not 500 crash

## Understanding

AC-4-11 is a **verification AC** — the implementation is already in place from AC-4-02.
What must be added is a **dedicated, deterministic test** that explicitly proves the
AIFailureError path produces `{"type":"error","message":"AI service unavailable"}` as
an SSE event, without a 500 crash.

When `streamMessage()` throws `AIFailureError` (wrapping any Anthropic non-2xx):
1. Headers are already sent (SSE stream is open)
2. The catch block in `service.ts` writes `data: {"type":"error","message":"AI service unavailable"}\n\n`
3. Calls `reply.raw.end()`
4. Returns (no rethrow — AIFailureError never reaches global handler per C13)

The AC-4-02 test in `messages.test.ts` already handles the error case gracefully as
a "soft" fallback when the API key is invalid, but this is not a deterministic test.
AC-4-11 requires a test that **forces** `AIFailureError` every run.

## Constraints That Apply

- **C13** — AIFailureError caught INSIDE chat service, never reaches global handler.
  The global handler is for AppError only.
- **C14** — SSE uses `reply.raw`. Error events must be written via `reply.raw.write()`, not `reply.send()`.
- **CLAUDE.md rule** — "Never mock authentication in integration tests."
  Mocking `streamMessage` (the Claude client) is distinct from mocking auth — this is allowed.
  Real Supabase auth + real DB required for setup.

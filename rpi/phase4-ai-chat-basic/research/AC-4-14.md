# Research: AC-4-14 — Conversation history included on subsequent turns

## Understanding

AC-4-14 is a **verification AC** — the implementation is already correct in `service.ts`.

The 10-step pipeline already handles history:
- **Step 1** persists the user message to `ChatMessage`
- **Step 3** fetches ALL messages for the session ordered by `createdAt asc`
- Step 3's result includes: previous user+assistant exchanges **plus** the current user message
  (persisted moments earlier in step 1)
- **Step 6** passes the full `historyMessages` array to `streamMessage()` as the `messages`
  parameter, which passes it directly to the Claude API `messages` field

On turn 2 the DB state before step 6 is: `[user1, assistant1, user2]`
Claude API receives `messages: [{role:'user', ...}, {role:'assistant', ...}, {role:'user', ...}]`
— correctly alternating, ending with user message.

The `role` conversion is handled by `.toLowerCase()` on the DB enum value (`USER` → `user`,
`ASSISTANT` → `assistant`) — matches what the Claude API expects.

What's missing: a **dedicated test** that deterministically proves history is passed on
subsequent turns, with the correct message sequence in the `messages` argument.

persisted in step 1).

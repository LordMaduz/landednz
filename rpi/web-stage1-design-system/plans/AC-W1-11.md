# Implementation Plan: AC-W1-11

## Approach
Build a flexible `Input` UI primitive component supporting both text input and textarea variants with comprehensive state handling. The component uses TypeScript discriminated unions to provide type-safe APIs for each variant, implementing the visual patterns from auth and chat mockups. Auto-expanding textarea behavior is implemented as an opt-in feature using React hooks for dynamic height calculation within the 24-72px range. All styling uses existing Tailwind design tokens to maintain consistency.

## File Changes
- **Create** `apps/web/src/components/ui/Input.tsx` — main component implementation with text/textarea variants, state handling, and auto-expand logic
- **Create** `apps/web/src/components/ui/Input.stories.tsx` — comprehensive Storybook stories covering all states and variants
- **Modify** `apps/web/src/components/ui/index.ts` — add barrel export for Input component

## Implementation Order
1. Create Input component TypeScript interfaces and discriminated union types
2. Implement base Input component with text variant and all state styling
3. Add textarea variant with conditional rendering logic
4. Implement auto-expanding textarea hook and integration
5. Add comprehensive Storybook stories for all variants and states
6. Update barrel exports in ui/index.ts
7. Verify all stories render correctly in Storybook

## Test Strategy
Run `npm run storybook` and verify all Input stories render correctly:
- Text variant with all states (default, hover, focus, error, disabled)
- Textarea variant with all states
- Auto-expanding textarea behavior (24-72px range)
- Error message display
- Email input type
- All states grid layout

None — AC-W1-11 creates a new UI primitive component that doesn't affect existing golden examples until integrated into forms in later stages.

# Research: AC-W1-11 — Input component

## Understanding

Build an `Input` UI primitive supporting both text input and textarea variants.
Component must handle label, placeholder, error, and disabled states. Error state
displays `--color-error` border with an error message. All states verified via
Storybook stories.

Based on mockup patterns from auth screen (email input) and chat interface (textarea),
the component uses focus states with colored borders and subtle box-shadow effects.
Auto-expanding textarea behavior (24-72px height range) follows the chat interface pattern.

## Functions / Routes / Tests

**Component API:**
```typescript
export type InputVariant = 'text' | 'textarea'

export interface InputProps {
  variant?: InputVariant       // default: 'text'
  label?: string              // Optional label above input
  error?: string              // Error message (shows error state)
  disabled?: boolean          // Disabled state
  placeholder?: string        // Placeholder text
  className?: string

  // For text input
  type?: 'text' | 'email' | 'password'  // when variant='text'

  // For textarea
  rows?: number               // when variant='textarea', default: 1
  autoExpand?: boolean        // Auto-expand height 24-72px (default: false)

  // Standard HTML attributes
} & (InputVariant extends 'text'
  ? React.InputHTMLAttributes<HTMLInputElement>
  : React.TextareaHTMLAttributes<HTMLTextAreaElement>)
```

## Ambiguities / Questions

**Auto-expand behavior clarification:**
- Chat mockup shows auto-expanding textarea (24-72px height). Should this be the default
  behavior for all textareas, or an opt-in `autoExpand` prop?
- **Resolution**: Make it opt-in via `autoExpand?: boolean` prop (default false) to avoid
  breaking existing form layouts that expect fixed textarea height.

**Label positioning:**
- Mockups show labels above inputs. Standard pattern is label → input → error message
  vertically stacked.

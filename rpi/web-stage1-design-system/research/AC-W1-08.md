# Research: AC-W1-08 — ProgressBar: deterministic + indeterminate in Storybook

## Understanding

Build a `ProgressBar` primitive with two modes:
- **Deterministic**: accepts a `value` prop (0–100), renders a filled bar that transitions its `width` over 0.4s as the value changes
- **Indeterminate**: renders a pulsing opacity animation on the fill bar (same "pulse" pattern as the Skeleton component) for when the progress percentage is unknown

The onboarding mockup shows a _segmented_ progress bar (individual segment divs colored primary or border), but that is a feature-specific layout component. The primitive we build here is a standard single-bar fill component. The segmented layout will be composed from this primitive or built separately in Stage 3.

The Storybook story must include an interactive `value` control (Storybook's built-in args range control, 0–100).

## Props API

```typescript
export interface ProgressBarProps {
  value?: number          // 0–100 (required for deterministic mode)
  indeterminate?: boolean // enables pulse animation; overrides value
  size?: 'sm' | 'md'     // sm=4px (h-1), md=8px (h-2)
  label?: string          // aria-label for screen readers
  className?: string
}
```

Default size: `sm` (4px height matches onboarding mockup's 4px segment height).

## Visual Design

- **Track**: `bg-border` (#E5E3E0) — matches the inactive segment colour in the onboarding mockup
- **Fill**: `bg-primary` (#1B6B6D)
- **Border radius**: `rounded-full` (Tailwind default, pill shape on both track and fill)
- **Height**: `h-1` (4px) for `sm`, `h-2` (8px) for `md`
- **Fill transition**: `transition-all duration-fill` (requires new `duration-fill: '400ms'` token)
- **Indeterminate**: fill fixed at ~60% width, opacity pulses 0.4→0.7→0.4 at 1.5s

## Accessibility

- `role="progressbar"` on the outer container
- `aria-valuenow={value}` for deterministic mode; omit for indeterminate
- `aria-valuemin={0}`, `aria-valuemax={100}` always present
- `aria-label` from the `label` prop (or default `"Progress"`)
- Fill bar is decorative — `aria-hidden="true"` on the inner fill div

## Constraints That Apply

- **CW01**: No raw hex or px values in component file. `bg-primary`, `bg-border`, `h-1`, `h-2`, `rounded-full`, `duration-fill`. New `duration-fill: '400ms'` added to `tailwind.config.ts`.
- **CW02**: Storybook stories required covering all states.
- **CW03**: Reduced motion — wrap pulse keyframe in `@media (prefers-reduced-motion: no-preference)`. In reduced motion mode, indeterminate bar renders static (no animation). Deterministic bar sets `transition-duration: 0s` via `motion-safe:duration-fill` or a `prefers-reduced-motion` CSS override in globals.css.

## Ambiguities / Questions

One minor ambiguity resolved during research:
- **Indeterminate animation type**: Spec says "pulse". Two interpretations: (a) opacity pulse (0.4→0.7→0.4) matching the Skeleton spec's explicit description, or (b) a sliding shimmer bar. Choosing (a) — opacity pulse — for consistency with Skeleton's named animation pattern. Both components will share the same `pulse` keyframe in globals.css.
- **Segmented vs standard bar**: The onboarding mockup shows a segmented layout. The primitive is a standard filled bar; the segmented feature component is Stage 3 work.

None requiring human clarification.

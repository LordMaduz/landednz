# Research: AC-W1-06 — Card component with states and padding variants

## Understanding

Build a `Card` UI primitive with four visual states (default, hover, selected, error) and three padding variants (compact, default, spacious). The hover state includes a shadow transition at 0.15s. Requires a Storybook story showing all states.

## Files Involved

**Create:**
- `apps/web/src/components/ui/Card.tsx` — Card component
- `apps/web/src/components/ui/Card.stories.tsx` — Storybook stories for all states

**Modify:**
- `apps/web/src/components/ui/index.ts` — add Card export (if barrel exists)

## Functions / Routes / Tests

**Component API:**
```typescript
interface CardProps {
  state?: 'default' | 'hover' | 'selected' | 'error'
  padding?: 'compact' | 'default' | 'spacious'
  children: React.ReactNode
  className?: string
  onClick?: () => void
}
```

**State → Tailwind mapping:**
| State | Background | Border | Shadow |
|-------|-----------|--------|--------|
| default | bg-bg-card | border-border | shadow-card |
| hover | bg-bg-card | border-border-hover | shadow-card-hover |
| selected | bg-primary-light | border-primary | shadow-card |
| error | bg-error-light | border-error/30 | shadow-card |

**Padding variants:**
- compact: `p-3` (12px)
- default: `p-6` (24px — space-6)
- spacious: `p-8` (32px)

**Hover transition:** `transition-all duration-150` (0.15s)
**Border radius:** `rounded-card` (12px — already in tailwind.config.ts)

**Storybook stories:**
- Default state
- Hover state
- Selected state
- Error state
- AllPaddingVariants gallery

## Constraints That Apply

- **CW01:** All tokens via Tailwind classes — no raw hex or px in component. `border-error/30` uses Tailwind opacity modifier which is valid.
- **CW02:** Storybook story required covering all 4 states.
- **CW03:** Transition must respect `prefers-reduced-motion` — `transition-all duration-150` is safe; global CSS in `globals.css` already sets transition-duration to 0s for reduced motion.
- All tokens needed already exist in `tailwind.config.ts`: `shadow-card`, `shadow-card-hover`, `rounded-card`, `bg-bg-card`, `border-border`, `border-border-hover`, `primary-light`, `border-primary`, `error-light`, `border-error`.

## Ambiguities / Questions

- **`border-error/30` opacity modifier**: The spec says "error border at 0.3 opacity". Tailwind's opacity modifier (`border-error/30`) should work if `error` is defined in tailwind.config as a color (it is: `#C75B4A`). This is valid.
- **Hover as a CSS state vs explicit prop**: The spec mentions a `hover` state — this could mean either CSS `:hover` pseudo-class (automatic) or an explicit `state='hover'` prop (manual). Looking at the mockup usage for Storybook, we need an explicit `state` prop to render stories. The component should use CSS `:hover` for interactive use but allow `state` override for Storybook — OR simply use the `state` prop for both. The cleaner approach: use an explicit `state` prop that can be overridden, and in Storybook show each state directly. For real interactive usage, consumers apply hover via CSS state or pass `state` dynamically.

None identified as blockers — proceeding with explicit `state` prop approach.

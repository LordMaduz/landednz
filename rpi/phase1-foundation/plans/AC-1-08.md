# Implementation Plan: AC-1-08 (+ AC-1-09)

## Approach
Add a `POST /auth/verify` endpoint that verifies a Supabase ES256 JWT using JWKS discovery via the `jose` library, upserts the user into our DB, and returns `{ userId, email, isNewUser, hasProfile }`. AC-1-09 (invalid JWT → 401) is implemented simultaneously — it is the error path of the same handler. `isNewUser` is determined by attempting a `create` and catching the Prisma `P2002` unique constraint error (cleaner and race-safe compared to upsert + timestamp comparison).

## Implementation Order

1. **Install `jose`** — `npm install jose` in `apps/api`
2. **`config.ts`** — add `supabaseUrl: requireEnv('SUPABASE_URL')`
3. **`auth.service.ts`** — implement `verifyAndUpsertUser(token: string)`:
   - `createRemoteJWKSet` from `jose` pointing at `${config.supabaseUrl}/auth/v1/.well-known/jwks.json`
   - `jwtVerify(token, JWKS)` — catch `JWTExpired`, `JWSInvalid`, etc. → throw `AppError('INVALID_TOKEN', ..., 401)`
   - Extract `payload.sub` (userId) and `payload.email`
   - Attempt `db.user.create({ data: { id: userId, email } })` — catch Prisma `P2002` → `isNewUser: false`
   - `db.userProfile.count({ where: { userId } }) > 0` → `hasProfile`
   - Return `{ userId, email, isNewUser, hasProfile }`
4. **`auth.route.ts`** — implement `registerAuthRoutes(app)`:
   - `POST /auth/verify` — extract Bearer token from `Authorization` header
   - Missing header → throw `AppError('INVALID_TOKEN', 'Missing Authorization header', 401)`
   - Call `verifyAndUpsertUser(token)` — AppError propagates to global handler
   - Return 200 with `{ userId, email, isNewUser, hasProfile }`
5. **`server.ts`** — import and call `registerAuthRoutes(app)` in `buildApp()`

## Test Strategy

**Without Google OAuth** — use Supabase admin API to create an email/password test user:

```bash
# 1. Get anon key and service role key
supabase status

# 2. Create test user (one-time)
curl -s -X POST "http://127.0.0.1:54321/auth/v1/admin/users" \
  -H "apikey: {service_role_key}" \
  -H "Authorization: Bearer {service_role_key}" \
  -H "Content-Type: application/json" \
  -d '{"email":"test@landednz.test","password":"Test1234!","email_confirm":true}'

# 3. Sign in to get JWT
JWT=$(curl -s -X POST "http://127.0.0.1:54321/auth/v1/token?grant_type=password" \
  -H "apikey: {anon_key}" \
  -H "Content-Type: application/json" \
  -d '{"email":"test@landednz.test","password":"Test1234!"}' | jq -r '.access_token')

# 4. AC-1-08: First call — expect 200, isNewUser: true
curl -s -X POST http://localhost:3000/auth/verify \
  -H "Authorization: Bearer $JWT" | jq .
# → { userId, email, isNewUser: true, hasProfile: false }

# 5. AC-1-08: Second call — expect 200, isNewUser: false (idempotency)
curl -s -X POST http://localhost:3000/auth/verify \
  -H "Authorization: Bearer $JWT" | jq .
# → { userId, email, isNewUser: false, hasProfile: false }

# 6. AC-1-09: Invalid token — expect 401
curl -s -X POST http://localhost:3000/auth/verify \
  -H "Authorization: Bearer invalid_token" | jq .
# → { error: "INVALID_TOKEN", message: "..." }
```

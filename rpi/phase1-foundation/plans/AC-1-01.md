# Implementation Plan: AC-1-01 — pgvector available after docker compose up

**Constitutional Validator:** PASS (0 violations, all 16 constraints checked)

---

## Approach

Create a `docker-compose.yml` at the monorepo root using the `pgvector/pgvector:pg16` Docker image (not vanilla `postgres:16`). Mount a `docker/init.sql` init script via the `docker-entrypoint-initdb.d/` mechanism so that `CREATE EXTENSION IF NOT EXISTS vector;` runs automatically when the container first initialises.

The extension is enabled at the Docker layer — not in a Prisma migration — because:
1. It must exist before any Prisma migration runs (AC-1-02 depends on it)
2. Putting `CREATE EXTENSION` in a migration is fragile on managed DB providers (Railway, Supabase)

## Implementation Order

1. Create `docker/init.sql` — single SQL statement enabling the vector extension
2. Create `docker-compose.yml` — references `pgvector/pgvector:pg16`, mounts init script, exposes port 5432
3. Add `DATABASE_URL` to `.env.example`

## Test Strategy

Exact verification from AC-1-01 (REQUEST.md + 12-build-specification.md §3.3):

```bash
docker compose up -d
docker compose exec postgres psql -U postgres -d landednz \
  -c "SELECT extname FROM pg_extension WHERE extname = 'vector';"
# Expected: 1 row returned
```

# Implementation Plan: AC-1-03 (+ AC-1-04)

## Constitutional Validation
PASS — 16/16 constraints checked, 0 violations.

## Approach
Build the full Fastify server scaffold and health endpoint in one unit.
AC-1-03 and AC-1-04 are two branches of the same handler — no reason to split them.
The health route uses `prisma.$queryRaw` SELECT 1 to probe DB connectivity.
The $queryRaw result MUST have the BigInt replacer applied (C10) before any use,
even though the result itself is not returned in the response body — only the
connectivity success/failure outcome is used.
Returns 200 on success and 503 on failure.

The 503 path returns directly from the handler (not via AppError) because DB
unreachability is an infrastructure failure, not a business logic failure (C13 allows this —
AppError is for expected business failures). A comment in the code documents this.

## Key Implementation Notes

### BigInt handling (C10)
In health.route.ts, apply the BigInt replacer to $queryRaw even though result is unused:
```typescript
// C10: $queryRaw can return BigInt — always apply replacer even when result is not returned
const result = await db.$queryRaw<unknown[]>`SELECT 1`
JSON.stringify(result, (_, v) => typeof v === 'bigint' ? Number(v) : v)
```

### 503 path (C13)
```typescript
// Infrastructure failure — not a business logic failure, so not AppError.
// Returned directly as 503 with error message.
reply.status(503).send({ status: 'error', message: 'Database unreachable' })
```

# Research: AC-1-09 — POST /auth/verify invalid JWT → 401

## Understanding

AC-1-09 is the **error handling path** of the `POST /auth/verify` endpoint, implemented alongside AC-1-08 in the same route handler. While AC-1-08 covers the success case (valid JWT → 200 with user data), AC-1-09 ensures that all invalid JWT scenarios return proper 401 errors with structured error responses.

The endpoint must detect and handle:
- Missing `Authorization` header
- Malformed `Authorization` header (not `Bearer {token}` format)
- Invalid JWT signature (ES256 verification failure via JWKS)
- Expired JWT tokens
- JWT missing required claims (`sub`, `email`)

All invalid scenarios throw `AppError('INVALID_TOKEN', message, 401)` which the global error handler converts to: `{ error: "INVALID_TOKEN", message: "..." }`.

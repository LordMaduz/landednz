# Research: AC-1-03 — GET /health returns 200 { status: "ok", dbConnected: true }

## Understanding

Build the Fastify API server scaffold from scratch — no `src/` directory exists yet.
The health endpoint must query the DB to confirm connectivity and return the result.
When the DB is reachable: HTTP 200 `{ status: "ok", timestamp: ISO8601, dbConnected: true }`.
When the DB is unreachable (AC-1-04): HTTP 503 `{ status: "error", message: string }`.

Both ACs share one route handler. Implementing AC-1-03 requires the same files as AC-1-04 —
they will be implemented together as one coherent unit.

## Files Involved

**New files to create:**
- `apps/api/src/server.ts` — Fastify entry point, registers plugins + routes, starts listening
- `apps/api/src/shared/db.ts` — Prisma singleton client
- `apps/api/src/shared/logger.ts` — pino logger (structured, no console.log ever)
- `apps/api/src/shared/config.ts` — env var validation at startup (DATABASE_URL required)
- `apps/api/src/shared/errors.ts` — AppError class with typed ErrorCode
- `apps/api/src/shared/plugins/error-handler.ts` — global Fastify error handler for AppError
- `apps/api/src/features/health/health.route.ts` — GET /health handler

**Existing files to modify:**
- `apps/api/package.json` — add fastify + pino + ts-node as dependencies

## Functions / Routes / Tests

**Route:**
```
GET /health
→ 200: { status: "ok", timestamp: string, dbConnected: boolean }
→ 503: { status: "error", message: string }
```

**DB connectivity check:** `prisma.$queryRaw\`SELECT 1\`` inside a try/catch.
- Success → `dbConnected: true`, HTTP 200
- Failure → `dbConnected: false`, HTTP 503

**No test file required for this AC** — verification is hitting the endpoint directly
(per REQUEST.md: "Hit endpoint"). However, the route must compile with zero TS errors.

## Constraints That Apply

- **C02** — `core/` must be pure functions. Health check uses Prisma → it belongs in `features/health/`, not `core/`. ✓
- **C13** — Expected failures use `AppError`. DB unreachable is an infrastructure failure — caught in handler, returns 503 directly (not thrown as AppError since it's not a business logic failure).
- **code-quality** — No `console.log`. Use `logger` from `shared/logger.ts`.
- **code-quality** — Every async operation handles errors explicitly. Health route is `async`.
- **tsconfig** — strict mode, ES2022, commonjs. No `any` without comment.

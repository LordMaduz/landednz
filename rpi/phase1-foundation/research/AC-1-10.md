# Research: AC-1-10 — App shell launches + bottom tabs on Expo Go

## Understanding

Bootstrap the entire React Native mobile app from scratch. `apps/mobile` currently contains
only a `CLAUDE.md` — no Expo project exists. AC-1-10 requires:

1. A working Expo project that launches in Expo Go (no custom native modules)
2. Placeholder screens for the app's core navigation destinations
3. Bottom tab navigation connecting those screens

"Placeholders acceptable — no content required" means each tab screen can be a simple
`<Text>Screen Name</Text>` component. No product logic, no API calls, no auth.

**Tab structure (inferred from spec):**
- **Roadmap** — core feature tab (RoadmapScreen)
- **Chat** — AI advisor tab (ChatScreen)
- **Profile** — user/account tab (ProfileScreen)

This matches the `ChatEntryPoint` enum (ROADMAP, NAVIGATION entries imply distinct tabs)
and the screens listed in `apps/mobile/CLAUDE.md`.

## Constraints That Apply

- **Mobile only** — no API/shared code changes. AC-1-10 is purely the mobile app shell.
- **No custom native modules** — Expo Go cannot run them. RevenueCat/Apple Sign-In are
  Phase 3+ concerns. Keep deps to Expo-compatible only.
- **bundleIdentifier must be `com.landednz.app`** — per CLAUDE.md gotcha, this must match
  App Store Connect. Set it now and never change it.
- **API base URL via env var** — `EXPO_PUBLIC_API_URL` (not wired in Phase 1 but must be
  the pattern for Phase 2 onwards per CLAUDE.md)
- **`packages/types/` for shared types** — no API calls in Phase 1, so this is structural
  only. AC-1-12 will verify the import works.

# Research: AC-1-06 — Google OAuth end-to-end on Expo Go

## Understanding

Complete the Google OAuth sign-in flow so that:
1. A user can tap "Sign in with Google" in Expo Go
2. The system browser opens, the user authenticates with Google
3. Supabase creates an `auth.users` record
4. The app calls `POST /auth/verify` with the JWT → creates a `User` record in the app DB
5. The app navigates to the main tab screens

The API side (`POST /auth/verify`) is already implemented and PASS from AC-1-08/09.
This AC is entirely mobile + Supabase config work.

Verification: live interactive flow — not a unit test. Must be run manually on Expo Go.

## Functions / Routes / Tests

**Auth flow (end-to-end):**
```
1. LoginScreen: tap "Sign in with Google"
2. supabase.auth.signInWithOAuth({ provider: 'google', redirectTo: makeRedirectUri({ scheme: 'landednz' }) })
3. expo-web-browser opens Supabase OAuth URL → user consents → Supabase creates auth.users
4. Supabase redirects to landednz://auth/callback?access_token=...&refresh_token=...
5. useAuth hook intercepts deep link → supabase.auth.setSession(...)
6. POST /auth/verify with Bearer {access_token} → app DB User record created
7. useAuth exposes session → App.tsx gates to tab navigator
```

**Key implementation notes:**
- `makeRedirectUri({ scheme: 'landednz' })` returns the correct redirect per environment (Expo Go vs standalone)
- `skip_nonce_check = true` required in Supabase config for local Google auth (config.toml comment states this explicitly)
- Supabase SDK needs `AsyncStorage` from `@react-native-async-storage/async-storage` for session persistence

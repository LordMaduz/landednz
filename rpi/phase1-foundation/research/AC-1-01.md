# Research: AC-1-01 — pgvector available after docker compose up

## Understanding

Stand up a `docker-compose.yml` at the monorepo root that runs PostgreSQL 16 with the pgvector extension enabled. The acceptance criterion is purely infrastructural: `SELECT extname FROM pg_extension WHERE extname = 'vector'` must return one row after `docker compose up -d`.

The key requirement is using the `pgvector/pgvector:pg16` Docker image — NOT vanilla `postgres:16`. The vanilla image doesn't include the pgvector shared library, so `CREATE EXTENSION vector` would fail even if attempted. The `pgvector/pgvector:pg16` image includes the library pre-installed.

The extension still needs to be explicitly created — the image installs the library but doesn't auto-enable it. This requires either:
1. An init SQL script (`docker-entrypoint-initdb.d/`) that runs `CREATE EXTENSION IF NOT EXISTS vector;`
2. Or inclusion in the first Prisma migration

**Decision:** Use an init SQL script. This is cleaner because:
- The extension must exist before Prisma migrations run (AC-1-02 depends on it)
- Keeping infra setup in Docker is the right separation of concerns
- A migration that `CREATE EXTENSION` is fragile on managed DB providers

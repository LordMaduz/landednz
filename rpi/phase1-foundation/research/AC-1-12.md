# Research: AC-1-12 — packages/types imported by both apps

## Understanding

Create the `packages/types/` shared package and wire it into both workspaces so
TypeScript can resolve `from '@landednz/types'` in both `apps/api` and `apps/mobile`.

The `packages/types/index.ts` is the contract between mobile and API — all types that
cross the boundary (onboarding enums, task status, error shapes) live here so neither
side redefines them.

**Current state:**
- Root `package.json` workspaces already includes `"packages/types"` ✅
- `packages/` directory does NOT exist yet
- No path mappings in either workspace tsconfig

**Verification target:** `tsc --noEmit` passes in both workspaces after an actual
import of `@landednz/types` exists in each. TypeScript must resolve the import.

## Files Involved

**New files to create:**
- `packages/types/package.json` — name: `@landednz/types`, main: `index.ts`
- `packages/types/tsconfig.json` — TypeScript config for the types package
- `packages/types/index.ts` — all type definitions from spec §3.2.3

**Modify — workspaces:**
- `apps/api/package.json` — add `"@landednz/types": "*"` to dependencies
- `apps/api/tsconfig.json` — add `paths` pointing to `../../packages/types`
- `apps/mobile/tsconfig.json` — add `paths` pointing to `../../packages/types`

**New files — verification imports:**
- `apps/api/src/shared/types.ts` — re-exports from `@landednz/types` (legitimate; avoids
  each feature importing directly from the package path)
- `apps/mobile/src/services/api.ts` — imports types from `@landednz/types` (already
  planned in CLAUDE.md as the location for all API calls)

## Known Failure Points

- **Workspace not linked** — root `package.json` already has `packages/types` in workspaces,
  but `packages/` directory must physically exist before `npm install` links it.
  Run `npm install` from root after creating the package.
- **Path mappings required in both tsconfigs** — npm workspace linking alone is not enough
  for TypeScript resolution. Both `tsconfig.json` files need `paths` entries.
- **Expo tsconfig base** — `apps/mobile/tsconfig.json` extends `expo/tsconfig.base` which
  may have its own `moduleResolution` settings. The paths must be compatible.

## Constraints That Apply

- **code-quality**: Never redefine enums that exist in `packages/types/index.ts`
- **code-quality**: Shared types stay in `packages/types/` — no duplication in apps
- Enums must match Prisma schema exactly (cross-checked above — all match)

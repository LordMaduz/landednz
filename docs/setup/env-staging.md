# Environment variables per platform

Names only; never put values in git. "Checklist" items are in [deploy-runbook.md](deploy-runbook.md) under "Owner prerequisites".
Source of truth for the API names: `apps/api/src/shared/config.ts`; for the web app: `apps/web/.env.example`.

## Render: staging API (`render.yaml`)

| Name | Set | Value comes from |
| --- | --- | --- |
| `NODE_ENV`, `AI_MODE`, `ANTHROPIC_MODEL`, `CHAT_DAILY_CAP`, `TRUST_PROXY`, `BETA_MODE` | in `render.yaml` | fixed by the plan (`production`, `live`, `claude-sonnet-5-5`, `10`, `true`, `true`) |
| `DATABASE_URL` | dashboard | Supabase checklist item, staging session pooler URL |
| `SUPABASE_URL` | dashboard | Supabase item, staging project URL |
| `SUPABASE_PUBLISHABLE_KEY` | dashboard | Supabase item, staging publishable key |
| `SUPABASE_SECRET_KEY` | dashboard | Supabase item, staging secret key |
| `CORS_ORIGIN` | dashboard | staging web origin (Vercel Preview URL) |
| `ANTHROPIC_API_KEY` | dashboard | Anthropic item, `landednz-staging` key |
| `OPENAI_API_KEY` | dashboard | OpenAI item |
| `SENTRY_DSN` | dashboard | Sentry item, `landednz-api` DSN |
| `ADMIN_API_KEY` | dashboard, optional | generated by the owner |

`PORT` is set by Render. Never set `CONTENT_ALLOW_UNVERIFIED` or `RATE_LIMIT_PER_MINUTE` on a deployed API.

## Railway: production API (`railway.json`)

Same names as Render. Differences: set every value in the Railway dashboard, with `NODE_ENV=production`, `AI_MODE=live`, `ANTHROPIC_MODEL=claude-sonnet-5-5`, `TRUST_PROXY=true`, `BETA_MODE=true`.
Values come from the production side: `landednz-prod` Supabase project, the `landednz-prod` Anthropic key, the same OpenAI key, `CORS_ORIGIN` = the production web origin, `CHAT_DAILY_CAP` as decided for production.
`PORT` is set by Railway.

## Vercel: Preview scope (= staging)

| Name | Value comes from |
| --- | --- |
| `NEXT_PUBLIC_API_URL` | Render staging API URL |
| `NEXT_PUBLIC_SITE_URL` | staging web URL |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase item, staging project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase item, staging publishable key |
| `NEXT_PUBLIC_AUTH_PASSWORD_ENABLED` | `true` on staging |
| `NEXT_PUBLIC_SENTRY_DSN` | Sentry item, `landednz-web` DSN |
| `NEXT_PUBLIC_POSTHOG_KEY`, `NEXT_PUBLIC_POSTHOG_HOST` | PostHog item |
| `SENTRY_AUTH_TOKEN` | Sentry item, auth token (build time only) |

## Vercel: Production scope

Same names as Preview, with production values: Railway API URL, `https://landednz.co.nz` for `NEXT_PUBLIC_SITE_URL` (Domain item), `landednz-prod` Supabase values, `NEXT_PUBLIC_AUTH_PASSWORD_ENABLED=false` (Google sign-in only).

## GitHub Actions (Settings → Secrets and variables → Actions)

| Name | Kind | Used as in `staging.yml` | Value comes from |
| --- | --- | --- | --- |
| `STAGING_SUPABASE_SECRET_KEY` | secret | `SUPABASE_SECRET_KEY` | Supabase item, staging secret key |
| `STAGING_SUPABASE_URL` | variable | `NEXT_PUBLIC_SUPABASE_URL` | Supabase item, staging project URL |
| `STAGING_SUPABASE_ANON_KEY` | variable | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase item, staging publishable key |
| `STAGING_API_URL` | variable | `NEXT_PUBLIC_API_URL`, API warm-up, `health.yml` | Render staging API URL |
| `STAGING_WEB_URL` | variable | `BASE_URL`; `staging.yml` is skipped while empty | Vercel Preview URL |
| `PROD_API_URL` | variable | `health.yml` | Railway API URL |
